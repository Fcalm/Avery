# Avery 归档对话管理调研与方案

调研日期：2026-11-04。交付范围：独立可交互 HTML 原型与调研报告；不修改 Avery 应用代码。

## 结论

入口采用 **设置 → 已归档对话**，沿用现有设置分类导航。列表只显示会话标题、所属项目、自动清理剩余时间和恢复／删除操作；提供标题搜索、项目筛选和排序。删除与恢复均需二次确认。

**自动清理不是归档的通用含义。** 本次按用户要求展示清理倒计时，原型暂以“归档后保留 30 天”演示。30 天是本次方案建议，既不是 Avery 现有规则，也不是从竞品归档规则中直接沿用。正式开发前需确定清理周期；这不影响本轮原型评审。

## 主流产品对比

本轮查阅官方产品文档、官方帮助中心及 Cursor 官方域名下的支持讨论；未登录竞品账户实测。各产品的客户端、协议能力与项目管理分别标明，不能互相推定。

| 产品及观察范围 | 归档与恢复 | 删除及确认 | 保留／自动清理 | 对 Avery 的启示 |
| --- | --- | --- | --- | --- |
| Codex：官方 App Server 协议 | 归档将记录移到归档目录；归档记录需专门查询；取消归档可恢复到活动目录 | 支持永久删除活动或归档记录，并涉及其派生子会话。协议文档不能证明桌面界面是否提供确认框 | 所查协议未规定归档记录的自动删除天数 | 归档应有独立管理入口；恢复与永久删除应是明确分开的操作。[1] |
| Cursor：Agents 窗口与 IDE 历史的支持答复 | 2026-06-18 支持讨论说明：Agents 窗口使用 Archive 移出活动列表，可恢复 | 同一答复说明永久删除仍在常规 IDE 的历史下拉中。所查材料未明确二次确认流程 | 未查到足以确认统一保留期限的当前官方文档 | 把高风险删除放入管理页面，但不要让用户为了删除在多个界面来回寻找。[2] |
| Claude：消费端会话及 Projects，作为相邻会话体验参考 | 官方确认的是**项目级归档**，归档后仍能访问会话，可取消项目归档；不能据此声称存在同样的单会话归档功能 | 单会话及批量删除均要求在确认提示中再次删除 | 删除后立即移出历史，后端在 30 天内删除；这不是“归档 30 天后删除”，也不能视为可恢复期 | 借鉴二次确认和项目归属；清晰区分“项目归档”与“会话归档”。[3][4] |
| Gemini：个人账号活动管理，作为自动清理参考 | 本轮官方活动管理文档未说明独立的归档恢复列表 | 可手动删除活动；所查页面未充分描述每一种删除入口的确认步骤和恢复能力 | 活动默认 18 个月自动删除，可选 3／18／36 个月或不自动删除；工作／学校账号另受管理员控制 | 自动清理须有清楚的期限；活动保留政策不能直接替代归档恢复政策。[5] |

证据限制：Cursor 的结论来自官方社区的支持讨论，低于明确的产品规范；旧历史文档地址现已跳转至文档首页，未用旧搜索摘要证明当前行为。Codex 行只陈述官方协议能力，不据此还原其客户端界面；Claude 与 Gemini 的范围也不外推至 Claude Code 或其他开发工具。所有“未查到”均表示本轮材料未证实，不表示产品一定不支持。

## Avery 当前状态

- 已有会话归档、取消归档和删除能力。归档仅使会话从“最近”移出，消息保留；当前归档确认框也是这一含义。
- 会话已带项目标识和项目名称，可复用现有归属信息；旧会话按未分组处理。
- 当前会话归档字段仅是布尔标记，未发现归档时间、自动清理截止时间或归档会话定期清理流程。因此现有数据不能直接计算真实倒计时。
- 当前删除会清理会话、消息与附件引用，并解除定时任务运行记录中的会话关联。原型不执行这些真实操作。

核对位置：`src/app/AppShell.tsx`、`src/features/settings/pages/SettingsPage.tsx`、`src/features/conversation/api/conversationQueries.ts`、`apps/backend/src/electron/repositories/conversation-repository.ts`、`packages/contracts/src/dto.ts`、`migrations/business/v10-conversation-pin-archive.sql`。

## 界面与交互决定

| 项目 | 本轮方案 |

| 入口 | 现有设置导航增加“已归档对话”。不同时增加第二个一级导航入口 |
| 信息 | 标题最多两行，悬停可看完整标题；项目独立一列，过长时悬停可看全名；未分组显式显示 |
| 倒计时 | 超过一天显示天与小时，不满一天显示小时与分钟，不满一小时显示分钟；24 小时内用克制的红色标识；悬停查看准确清理时间 |
| 默认排序 | 最早清理优先；支持最近归档优先；未设清理时间的历史对话排在清理排序末尾 |
| 搜索筛选 | 标题搜索可叠加项目筛选；标题旁计数对应当前筛选结果 |
| 恢复确认 | 显示完整标题、项目与恢复去向；确认后移出归档列表并提示“对话已恢复”；取消不改变记录 |
| 删除确认 | 标题为“永久删除对话？”，显示目标标题及“对话及其中的消息将被永久删除，无法恢复。”；确认按钮用红色 |
| 键盘与关闭 | 确认框默认聚焦“取消”；支持 Esc、关闭按钮、点击遮罩取消；焦点限制在确认框内；操作完成后回到邻近行操作按钮或搜索框 |
| 空态 | 真正空列表仅显示“暂无归档对话”；无搜索结果显示“没有找到匹配的对话”和“清除筛选” |
| 窄窗口 | 列表转换为紧凑行卡，标题、项目、剩余时间依次排列，恢复／删除仍可直接操作 |
| 视觉 | 复用项目松绿 `#17654f`、Segoe UI、Manrope 数据字体、Phosphor 图标及 14px 卡片／10px 控件圆角；确认框沿用项目 392px 规格 |

增加一个“删除所有对话”按钮，仅清空全部已归档对话，包含搜索或项目筛选未显示的记录。二次确认明确范围、总数量及不可恢复；取消不改变任何记录，空列表时禁用按钮。不提供多选、全选或“删除所选”。不加入统计卡片、引导说明、会话内容预览或第二层详情页面。

## 自动清理与边界

1. **期限建议**：新归档记录从归档成功时开始计算 30 天；重新归档重新计时，恢复后停止倒计时。不按会话创建时间或最近消息时间清理。
2. **旧记录**：没有可靠归档时间时显示“未设定”，不回推并补造截止时间，不静默清理。若需要迁移旧记录，应提前明确告知新的保留规则。
3. **用户知情**：正式启用限时清理时，原有归档确认框必须同步说明归档后保留多久；不能保留当前“消息仍保留”的笼统承诺后悄悄开启删除。列表右上角的期限也需与真实配置一致。
4. **恢复与清理同时发生**：确认操作时再次检查记录是否可恢复；已到期且已清理的记录提示“对话已自动清理”，不显示恢复成功。实际产品需以操作结果为准。
5. **项目不存在**：列表保留历史项目名称并标“已移除”；确认恢复说明会显示在“最近”的未分组列表。历史项目快照保持原样，不擅自绑定到别的项目。这是新增的展示规则建议。
6. **运行中的会话**：实际接入前应禁止对仍在执行或等待用户确认的会话进行永久清理；不能通过删除会话偷偷终止任务。正在运行的定时任务使用归档会话时，也须先处理任务状态。
7. **关联资料**：删除会话不应连带删除岗位、简历或其他会话引用的资料；附件按已有生命周期处理，定时任务运行历史保留。确认文案只承诺删除会话与消息，不承诺立即擦除所有引用文件。
8. **操作失败**：真实接入失败时保留原行并提示失败，不能先移除后宣称成功。本轮离线原型不伪造网络请求或失败回执。

## 原型范围与验收

入口文件：[index.html](index.html)，双击即可打开，字体图标内嵌，可离线使用。

原型含 8 条演示对话，覆盖多个项目、未分组、即将清理、长标题、项目已移除与历史无期限记录。支持搜索、筛选、排序、确认恢复、确认删除、取消、键盘关闭及空态。每 30 秒刷新剩余时间；到期仅移除原型内记录，确认时也会复查是否到期。

**操作仅作用于本页内存。刷新页面恢复初始示例；没有接入真实数据，也没有实现真实会话恢复、存储或后台自动清理。** 设置侧栏中的其他分类只用于呈现现有项目布局，不在本轮功能范围。

验收记录见 [验收结果.md](验收结果.md)。
