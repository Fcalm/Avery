# OfferGet（Avery）

OfferGet 是一款面向校招、实习招聘和毕业初期求职者的本地优先 AI 桌面应用。它希望把求职过程中反复出现的资料整理、简历修改、岗位记录、申请填写和进度跟踪放在同一个工作空间中，让模型真正使用你已经确认过的经历，而不是每次对话都从零开始了解你。

桌面应用当前显示的产品名称为 **Avery**。项目首先面向希望直接完成求职工作的普通用户，同时也为 Agent、Electron 和自动化方向的开发者提供可复现的运行时、Trace 与测评系统。

> 当前项目仍在持续开发中，首发平台为 Windows。你需要自行提供受支持模型服务的 API Key。涉及提交申请、上传材料、向招聘方发送消息等外部操作时，请检查页面内容和最终确认信息；OfferGet 不会绕过验证码、登录验证或招聘平台的安全限制。

## OfferGet 可以帮你做什么

### 建立可复用的求职档案

档案库用于保存项目经历、工作或实习经历、教育背景、技能证书以及其他求职资料。与把所有信息塞进一份长简历不同，档案库更像一组可以重复使用的事实卡片：你只需要维护一次真实经历，之后就可以让 Agent 根据不同岗位选择合适的内容。

档案支持分类、搜索、新增、编辑和删除。Agent 可以在获得授权的场景中读取档案；涉及公司、证书、学历等需要核实的硬事实时，生成内容应由用户确认后再使用。

### 编写和管理多份简历

你可以针对不同公司和岗位保留多份简历，指定当前供求职助手使用的版本，并查看简历的历史版本。重要版本可以单独标记，避免被常规版本清理策略移除。

求职助手能够读取当前简历和档案，帮助你重写描述、调整重点、补充量化表达或生成针对某份 JD 的版本。写入简历前会遵循当前确认权限；需要确认时，应用会先展示变更并等待用户决定。当前界面支持将简历导出为 HTML 或 PDF 文件，导出结果保存在本地工作空间中。

### 使用场景化求职助手

求职助手不是一个拥有无限权限的通用聊天机器人。每个新会话会固定一个场景，不同场景使用不同的提示词、工具白名单和确认策略：

- **默认场景**适合读取和整理简历、档案、附件以及用户授权的项目文件。它可以协助分析 JD、改写材料和维护 Todo，但不会在后台自行操作招聘网站。
- **投递场景**可以使用隔离浏览器读取网页、搜索页面中的岗位、填写普通表单、选择下拉项、上传已授权文件并完成受控提交。登录、验证码、异常字段和平台拦截仍需要用户接管。

会话支持五档思考强度和三档确认权限。确认权限只决定普通操作需要多频繁地询问你，不会扩大场景的工具范围，也不会绕过文件、网络或提交操作的安全边界。

### 整理岗位和追踪投递

岗位库用于记录公司、岗位名称、城市、薪资、经验要求、来源链接和完整 JD。你可以收藏岗位，按企业、岗位或城市搜索，并将关注的机会整理为稳定的本地记录。

投递管理以“待投递、已投递、测评与面试、已结束”等阶段展示申请进度。每条记录可以关联实际使用的岗位和简历，保存投递日期、下一步日期及备注，便于持续跟进，而不是把信息散落在聊天记录和表格中。

### 创建定时 Agent 任务

当你明确要求 Agent 在指定时间或按周期执行一条消息时，它可以创建 CronTask。任务支持单次、每日和按星期执行，也可以限制重复次数。创建前应用会说明这是无人值守执行并请求一次确认；到期后任务会打开独立会话执行，不会占用原有对话。

如果设备休眠或关机导致多个时间点错过，应用最多补执行最近一次，其余记录为 `missed`。定时执行依然受固定场景、工具白名单和网络边界约束。

## 快速开始

### 1. 安装并启动

普通用户应优先从项目的 [GitHub Releases](https://github.com/Fcalm/Avery/releases) 页面下载 Windows 安装包。安装后启动 Avery，按照首次启动向导创建本地工作空间。

如果 Releases 页面暂时没有适合当前版本的安装包，可以按照下方“开发者指南”从源码运行。请不要从非项目发布页下载要求你提供模型密钥的安装包。

### 2. 配置模型服务

在首次启动向导或“设置 → API 配置”中选择 Provider，并填写自己的 API Key：

- **DeepSeek**：可以同步当前账号可用的模型，并选择具体模型。
- **GLM**：使用智谱中国区官方接口和 `glm-5.3-flash` 模型。
- **自定义**：用于用户明确配置的兼容服务地址和模型名称。

先点击“测试连接”，确认网络和凭据有效，再保存配置。API Key 不会写入普通设置或业务数据库，而是交给 Electron 的系统安全存储能力加密保存。模型请求仍会把本轮必要的提示词和上下文发送给你选择的 Provider，因此请同时阅读相应服务商的隐私政策。

### 3. 先完善档案，再生成简历

建议先进入档案库，至少填写教育经历、项目经历、工作或实习经历、技能与目标岗位。资料越具体，Agent 越容易生成有依据的简历内容。

随后进入求职助手，新建默认场景会话，选择当前简历并描述目标，例如：

```text
请根据我的档案起草一份面向 Agent 工程师实习岗位的简历，突出工具编排和浏览器自动化经历。没有依据的数字请先问我。
```

完成后到简历库检查内容、设置当前版本并导出文件。不要直接使用未经核对的公司名称、证书、学历、时间或成果数字。

### 4. 保存岗位并准备申请

在岗位库新增目标岗位，尽量保存完整 JD 和申请链接。你可以先在默认场景中让 Agent 比较岗位要求与当前简历，确认能力差距并调整材料。

需要操作招聘页面时，请新建投递场景会话。首次进入某个平台通常需要你在独立浏览器窗口中手动登录。之后 Agent 可以在该隔离浏览器中继续搜索、阅读和填写；登录状态保存在 OfferGet 专用浏览器 Profile 中，不与系统浏览器混用。

### 5. 核对提交并持续跟进

提交前检查岗位、公司、简历版本、联系方式、附件和页面上的敏感问题。遇到验证码、登录失效、站点拦截或无法判断的字段时，请接管浏览器处理，不要要求 Agent 绕过平台限制。

投递完成后，在投递管理中确认状态并记录下一步日期。只有浏览器或工具返回可验证的成功回执时，才应把申请标记为已投递。

## 数据、隐私与安全边界

OfferGet 采用本地优先架构。简历、档案、岗位、投递记录、附件索引和 Agent Trace 默认保存在当前 Windows 用户的本地工作空间中；默认位置位于 `%APPDATA%\offerget\OfferGet Workspace`。应用提供本地备份与工作空间迁移能力，迁移采用复制、校验、切换流程，不会自动删除原目录。

需要注意以下边界：

- 模型推理不是本地完成的，请求会发送到你配置的模型 Provider。
- 投递场景访问的岗位页面会收到正常浏览器请求以及你主动填写或上传的信息。
- 浏览器 Cookie 和登录状态保存在独立 Profile 中，可以在设置页面清除，不会清理你的系统浏览器数据。
- 应用不会尝试绕过验证码、风控、登录校验或网站访问限制，也不保证所有招聘网站都能稳定自动化。
- 开发者模式中的日志、Trace 和测评数据用于本地诊断；它们不应包含 API Key，但仍可能含有求职上下文，分享前请自行检查。

## 开发者指南

### 环境要求

- Windows 10/11；其他桌面平台目前不是发布验证目标。
- 可用的 Node.js 与 npm。依赖版本由 `package-lock.json` 固定，请使用 npm，不要混用 pnpm 或 yarn。
- 构建或调试 MarkItDown 附件解析 sidecar 时需要 Python；不涉及附件解析的普通前端、业务和 Agent 开发不需要 Python。浏览器执行器已经作为项目依赖提供，不需要手工安装全局 `agent-browser`。

### 从源码运行

克隆仓库并安装依赖：

```powershell
git clone https://github.com/Fcalm/Avery.git
cd Avery
npm ci
npm run build:packages
```

开发模式需要两个终端。第一个终端启动 Vite：

```powershell
npm run dev
```

第二个终端启动 Electron：

```powershell
npm start
```

Electron 默认连接 `http://127.0.0.1:5173`。如果需要使用其他开发服务器地址，可以在启动 Electron 前设置 `VITE_DEV_SERVER_URL`。

### 测试、构建与打包

```powershell
# 执行单元、契约和工作区测试
npm test

# 构建所有 packages、Backend、Desktop 和 Renderer
npm run build

# 构建 Windows 未安装目录包
npm run pack:dir

# 构建 Windows 安装包
npm run pack:win
```

浏览器、投递和测评功能还有独立的冒烟及评估脚本，具体入口可查看 `package.json`。涉及真实 Provider 或招聘网站的测试可能产生 API 费用或外部副作用，不应在不理解测试目标时直接运行。

## 项目结构

```text
Offerget/
├─ src/                         # React Renderer：页面、状态、组件与样式
├─ apps/
│  ├─ desktop/src/             # Electron Main、窗口、安全策略和桌面能力
│  └─ backend/src/             # Utility Process、业务服务、Agent Host 与 Worker
├─ packages/
│  ├─ contracts/               # 跨进程 DTO、Bridge、Schema 与错误契约
│  ├─ agent-sdk/               # Agent 模块接口、消息、工具和事件类型
│  ├─ agent-core/              # Agent Loop、调度、取消、压缩与运行约束
│  ├─ agent-module-host/       # 模块解析、版本校验和快照
│  └─ agent-modules-defaults/  # 默认 Provider、Prompt、Context 与工具实现
├─ electron/                   # Preload Bridge
├─ migrations/                 # 业务与可观测性数据库迁移
├─ skills/                     # 项目内 Agent Skills
├─ evals/                      # Prompt、安全和浏览器测评数据集
├─ tests/                      # 单元、契约、集成与前端测试
├─ scripts/                    # 构建、打包、冒烟和测评脚本
├─ tools/                      # MarkItDown 等独立辅助程序源码
└─ docs/                       # 产品、架构、Agent 设计与开发记录
```

运行时遵循 Renderer、Preload、Electron Main、Backend Utility Process、数据库 Worker 和 Agent Kernel 的职责分离。Renderer 不直接访问 Node.js、数据库或模型密钥；跨进程请求通过 `packages/contracts` 中的窄契约传递。更完整的设计请阅读：

- [界面设计规范](docs/DESIGN.md)
- [Agent 设计文档](docs/Agent-design/README.md)
- [版本路线图](docs/VERSION-ROADMAP.md)

## 参与开发

提交代码前请先阅读 [AGENTS.md](AGENTS.md)。项目要求 Bug 修复先复现和定位根因，新功能或较大修改在独立分支完成；提交信息使用 Conventional Commits，并且一次提交只包含一个逻辑变更。

修改后至少运行受影响范围的测试、类型检查和构建。涉及 Electron 安全、浏览器自动化、数据库迁移、简历写入或外部提交的改动，还需要验证权限边界、取消、迟到结果、幂等和失败恢复，不能用隐藏错误或扩大容错代替根因修复。

当前仓库在 `package.json` 中标记为 `UNLICENSED`，尚未授予通用开源许可证。除非仓库后续明确增加许可证文件，否则请不要假设代码可以被任意复制、分发或用于商业用途。
