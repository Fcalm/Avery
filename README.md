# Avery

Avery 是一款面向校招、实习和毕业初期求职者的 AI 桌面助手。你可以在这里整理个人经历、修改简历、收集岗位、填写申请并跟踪投递进度。资料默认保存在自己的电脑上，求职助手会使用你已整理的经历，减少反复介绍自己的时间。

你可以直接下载安装使用；如果想了解实现或参与开发，下方也提供了源码运行和测试指南。

> 当前为 Windows 测试版，需要自备模型服务的 API Key（调用密钥），模型使用费用由对应服务商收取。提交申请、上传材料或发送消息前，请核对内容；遇到登录或验证码时，需要你手动处理。

## Avery 可以帮你做什么

### 建立可复用的求职档案

把教育背景、项目、实习、工作经历和技能证书放进档案库，之后就能在不同简历中反复使用。求职助手可以根据岗位要求，从这些经历中挑选适合的内容。

你可以分类、搜索和编辑档案。求职助手会在授权范围内读取资料，生成后请核对公司、证书、学历等事实信息。

### 编写和管理多份简历

你可以针对不同公司和岗位保留多份简历，指定当前供求职助手使用的版本，并查看简历的历史版本。重要版本可以单独标记，避免被常规版本清理策略移除。

求职助手可以结合当前简历、档案和岗位描述（JD），帮你调整措辞、突出相关经历，生成适合目标岗位的版本。需要确认的修改会先展示给你，再由你决定是否写入。完成后可以导出为 HTML 或 PDF 文件，保存在本地。

### 使用场景化求职助手

新建会话时，你可以根据要做的事选择场景。场景决定助手能使用哪些功能：

- **默认场景**适合整理简历、档案、附件和已授权的项目文件，也可以分析岗位要求、改写材料和整理待办事项。
- **投递场景**可以通过 Chrome、Edge 或 ego lite 浏览招聘页面、查找岗位、填写表单、上传已授权文件，并按权限设置提交申请。登录、验证码和无法判断的字段需要你接管。

会话支持五档思考强度和三档确认权限。你可以调整助手分析问题的深度，以及操作前向你确认的频率；切换权限不会让助手获得场景之外的能力。

### 整理岗位和追踪投递

在岗位库中保存公司、岗位名称、城市、薪资、要求、申请链接和完整岗位描述。你可以手动添加，也可以从 BOSS、支持的企业官网或校招汇总入口采集岗位，再按条件筛选、收藏，并按薪资、匹配分数或入库时间排序。采集结果取决于网站公开信息和访问情况，可能少于设定数量。

投递管理按“待投递、已投递、测评与面试、已结束”等阶段展示进度。每条记录可以关联岗位和使用的简历，记下投递日期、下一步日期和备注，方便及时跟进。

### 创建定时 Agent 任务

你可以让助手在指定时间、每天或每周执行任务，也可以限制重复次数。完全信任模式会直接创建任务，其他权限档位需要你确认。到时间后，任务会在独立会话中执行，方便你回看结果。

任务需要电脑和应用处于可运行状态。休眠或关机期间错过多次任务时，恢复后最多补执行最近一次，其余会标记为错过。定时任务遵循原场景的权限和访问限制。

## 快速开始

### 1. 安装并启动

点击上方下载按钮，或前往 [GitHub Releases](https://github.com/Fcalm/Avery/releases)，选择最新版本中的 `Avery-Setup-版本号-x64.exe`。运行安装包，选择安装目录，启动后按向导创建本地工作空间。

安装包目前未签名，Windows 可能显示未知发布者提示，请确认文件来自本仓库的发布页。安装后可在“设置 → 通用”中检查更新，下载完成后由你确认安装并重启。`.blockmap` 和 `latest.yml` 供应用更新使用，手动安装只需下载 `.exe`。

### 2. 配置模型服务

在首次启动向导或“设置 → API 配置”中选择模型服务商，并填写自己的 API Key：

- **DeepSeek**：可以同步当前账号可用的模型，并选择具体模型。
- **GLM**：使用智谱中国区官方接口和 `glm-5.3-flash` 模型。
- **自定义**：填写兼容服务的接口地址、模型名称和密钥。

先点击“测试连接”，通过后保存。不同服务商的密钥和模型配置会分别保留，切换时无需重新填写。之后可以在对话输入框的模型菜单中切换已配置的模型，每个会话单独记住选择，下一条消息开始使用。

API Key 通过系统安全存储能力加密保存在本机。对话所需的资料仍会发送给你选择的模型服务商，请留意其隐私政策。

### 3. 先完善档案，再生成简历

建议先进入档案库，至少填写教育经历、项目经历、工作或实习经历、技能与目标岗位。资料越具体，Agent 越容易生成有依据的简历内容。

随后进入求职助手，新建默认场景会话，选择当前简历并描述目标，例如：

```text
请根据我的档案起草一份面向 Agent 工程师实习岗位的简历，突出工具编排和浏览器自动化经历。没有依据的数字请先问我。
```

完成后到简历库检查内容、设置当前版本并导出文件。不要直接使用未经核对的公司名称、证书、学历、时间或成果数字。

### 4. 保存岗位并准备申请

在岗位库手动添加或采集目标岗位，尽量保留完整岗位描述和申请链接。先让默认场景中的助手比较岗位要求与当前简历，再调整材料。

需要填写申请时，新建投递场景会话。在“设置 → 浏览器控制”中选择 Chrome、Edge 或 ego lite（默认 Edge），按页面指引手动加载随应用提供的 Avery 扩展，再点击“检测状态”确认接入成功。无需开启远程调试。

Avery 会使用所选浏览器已有的登录状态，仅操作自己的任务标签页。它不会接管你的其他个人标签页，也不会在任务结束时关闭整个浏览器。不同招聘网站的支持情况可能不同，遇到登录、验证码或访问限制时需要你处理。

### 5. 核对提交并持续跟进

提交前检查岗位、公司、简历版本、联系方式、附件和页面上的敏感问题。遇到验证码、登录失效、站点拦截或无法判断的字段时，请接管浏览器处理，不要要求 Agent 绕过平台限制。

投递完成后，在投递管理中确认状态并记录下一步日期。只有浏览器或工具返回可验证的成功回执时，才应把申请标记为已投递。

## 数据、隐私与安全边界

简历、档案、岗位、投递记录、附件索引和助手运行记录默认保存在本机，工作空间默认位于 `%APPDATA%\avery\Avery Workspace`。你可以在应用中备份资料或迁移工作空间；迁移会先复制并校验，再切换到新目录，原目录会保留。

需要注意以下边界：

- AI 回答由你配置的模型服务商生成，对话所需的内容会发送给该服务商。
- 投递场景访问的岗位页面会收到正常浏览器请求以及你主动填写或上传的信息。
- 浏览器任务使用 Chrome、Edge 或 ego lite 的现有登录状态；Avery 不清理个人浏览器的 Cookie 和登录数据。
- 应用不会尝试绕过验证码、风控、登录校验或网站访问限制，也不保证所有招聘网站都能稳定自动化。
- 日志、助手运行记录和测评数据用于本地排查问题，其中可能包含求职资料，分享前请检查并去除个人信息。

## 开发者指南

### 环境要求

- Windows 10/11；其他桌面平台目前不是发布验证目标。
- 可用的 Node.js 与 npm。依赖版本由 `package-lock.json` 固定，请使用 npm，不要混用 pnpm 或 yarn。
- 构建或调试 MarkItDown 附件解析 sidecar 时需要 Python；不涉及附件解析的普通前端、业务和 Agent 开发不需要 Python。浏览器操作通过随应用提供的扩展完成，不需要另装命令行浏览器执行器。

### 从源码运行

克隆仓库并安装依赖：

```powershell
git clone https://github.com/Fcalm/Avery.git
cd Avery
npm ci
npm run build:packages
```

开发模式需要两个终端。第一个终端启动 Vite：

```powershell
npm run dev
```

第二个终端启动 Electron：

```powershell
npm start
```

Electron 默认连接 `http://127.0.0.1:5173`。如果需要使用其他开发服务器地址，可以在启动 Electron 前设置 `VITE_DEV_SERVER_URL`。

### 测试、构建与打包

```powershell
# 执行单元、契约和工作区测试
npm test

# 构建所有 packages、Backend、Desktop 和 Renderer
npm run build

# 构建 Windows 未安装目录包
npm run pack:dir

# 构建 Windows 安装包
npm run pack:win
```

浏览器、投递和测评功能还有独立的冒烟及评估脚本，具体入口可查看 `package.json`。涉及真实 Provider 或招聘网站的测试可能产生 API 费用或外部副作用，不应在不理解测试目标时直接运行。

## 项目结构

```text
Avery/
├─ src/                         # React Renderer：页面、状态、组件与样式
├─ apps/
│  ├─ desktop/src/             # Electron Main、窗口、安全策略和桌面能力
│  ├─ backend/src/             # Utility Process、业务服务、Agent Host 与 Worker
│  └─ browser-extension/       # Chrome、Edge 和 ego lite 使用的浏览器扩展
├─ packages/
│  ├─ contracts/               # 跨进程 DTO、Bridge、Schema 与错误契约
│  ├─ agent-sdk/               # Agent 模块接口、消息、工具和事件类型
│  ├─ agent-core/              # Agent Loop、调度、取消、压缩与运行约束
│  ├─ agent-module-host/       # 模块解析、版本校验和快照
│  ├─ agent-modules-defaults/  # 默认 Provider、Prompt、Context 与工具实现
│  └─ application-benchmark/   # 本地模拟网申与测评环境
├─ electron/                   # Preload Bridge
├─ migrations/                 # 业务与可观测性数据库迁移
├─ skills/                     # 项目内 Agent Skills
├─ evals/                      # Prompt、安全和浏览器测评数据集
├─ tests/                      # 单元、契约、集成与前端测试
├─ scripts/                    # 构建、打包、冒烟和测评脚本
├─ tools/                      # MarkItDown 等独立辅助程序源码
└─ docs/                       # 产品、架构、Agent 设计与开发记录
```

运行时遵循 Renderer、Preload、Electron Main、Backend Utility Process、数据库 Worker 和 Agent Kernel 的职责分离。Renderer 不直接访问 Node.js、数据库或模型密钥；跨进程请求通过 `packages/contracts` 中的窄契约传递。更完整的设计请阅读：

- [项目架构](docs/ARCHITECTURE.md)
- [Agent 设计文档](docs/Agent-design/README.md)
- [版本路线图](docs/VERSION-ROADMAP.md)
