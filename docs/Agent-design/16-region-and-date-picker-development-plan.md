# 地区与纯点选日期控件：开发规划与进度

## 1. 问题与证据

科大讯飞招聘表单实测中，普通下拉和可直接输入的日期已经可用，但仍有两类复合控件失败：

- 月份选择器没有可编辑输入框，只提供年份入口和 1—12 月网格。Trace 中可见 `button "2026年"` 与 `gridcell "1月"` 至 `gridcell "12月"`，现有日期执行器仍按“查找输入框、填值、按 Enter”处理，因此返回 `date_editor_not_found`。
- 地区选择器要求完成省、市（以及可用时的区县）选择后，再点击当前弹层内的确认按钮。现有执行器把点击单选图标等同于选择完成，并把确认当成可选步骤；确认未识别时，通用弹层收尾会直接关闭并丢弃选择，最终返回 `selection_not_committed`。

问题属于动态控件执行状态机缺失，不应继续扩大普通下拉的模糊匹配范围。

## 2. 目标与边界

继续只向模型暴露 `BrowserFillForm`，不新增日期或地区专用工具。Host 内部增加两个专用执行流程：

```text
BrowserFillForm
  -> DatePickerExecutor
     -> 可输入日期
     -> 纯点选年/月/日
  -> RegionPickerExecutor
     -> 逐级选择
     -> 选中状态确认
     -> 弹层内确认
```

约束保持不变：

- 模型不能提供 JavaScript、CSS selector、DOM 路径或任意 CLI 参数。
- 候选年份、月份、日期、地区和确认按钮必须来自当前页面的新快照。
- 不点击上传、协议、暂存、预览或提交按钮。
- 个人浏览器扩展只执行随版本发布的固定表单模块，不新增模型可见的脚本工具。
- 每次状态推进后废弃旧 ref，使用有限轮询和固定动作上限。

## 3. DP-01：个人浏览器固定表单模块

动态控件执行器通过扩展内置 Content Script 完成临时语义标记和后置校验，Agent 不能提供或修改脚本正文。

实现：

- Browser Bridge 只调用扩展登记的固定表单操作，不接受任意表达式或 JavaScript。
- 对操作名称、输入 Schema 和消息大小做校验。
- 返回按值序列化的结果，不返回 DOM 节点或远程对象句柄。
- 不向 Agent 工具 schema 增加 `eval`，模型无法直接调用。
- 移除地区和日期执行器仅限 Electron 的限制，使两种浏览器复用同一状态机。

验收标准：

- [ ] 扩展 Runtime 能运行固定语义标记和布尔后置校验。
- [x] 非法编码、空表达式和超长表达式被拒绝。
- [x] Agent 工具列表中不存在任意脚本执行工具。

## 4. DP-02：纯点选日期状态机

日期执行器先检测可编辑输入框；不存在时进入点选模式：

```text
打开字段
  -> 读取目标 YYYY-MM[-DD]
  -> 识别当前年份与月份面板
  -> 年份不一致时打开年份面板
  -> 选择目标年份
  -> 等待月份网格刷新
  -> 选择目标月份
  -> 存在目标日期时选择日期
  -> 等待弹层关闭
  -> 校验原字段显示值
```

第一版重点覆盖页面当前能证明的直接年份入口和月份网格。完整日期仍优先使用可编辑输入路径；点选流程仅在日期网格能唯一确定目标日期时继续。目标年份不在当前可见年份面板、且无法可靠识别翻页语义时停止该字段，不猜测坐标或任意网格项。

验收标准：

- [x] 可输入日期沿用原路径，无回归。
- [x] `YYYY-MM` 能按目标年份和月份完成纯点击选择。
- [x] 日期网格能唯一确定目标日期时可继续选择日。
- [x] 每一步使用新快照，旧 ref 不复用。
- [x] 缺少年、月候选时返回明确失败原因，不误报成功。
- [x] 原字段值未更新时不计入 `filled`。

## 5. DP-03：地区选择与强制确认状态机

地区执行器把导航、选中和确认拆开：

```text
打开字段
  -> 选择省份
  -> 等待城市列表
  -> 选择城市
  -> 页面支持且资料包含区县时选择区县
  -> 验证末级选项处于 checked/selected/active 状态
  -> 在当前弹层内等待可用的确认按钮
  -> 点击确认
  -> 等待弹层关闭
  -> 校验原字段显示值
```

确认是该流程的强制提交步骤。找不到确认按钮、按钮未启用或确认后字段未更新时，不得使用通用关闭逻辑冒充成功。

验收标准：

- [x] 省、市两级按顺序选择。
- [x] 页面存在区县层时能继续选择最末级。
- [x] 自动提交型控件先验证字段；非自动提交型控件必须继续进入确认阶段。
- [x] 确认按钮只从当前可见动态弹层候选中识别，禁用按钮不进入候选。
- [x] 确认未完成时返回结构化原因，通用收尾只能用于失败恢复。
- [x] 确认后原字段显示已选地区，才计入 `filled`。

## 6. DP-04：验证范围

使用少量针对性测试，不进行全量端到端投递：

- 单元测试模拟年份入口、年份候选、月份网格与字段提交。
- 单元测试模拟省、市、选中控件、确认按钮和确认后的显示值。
- 回归可输入日期、普通下拉、连续动态字段及取消/超时传播。
- 运行 Backend TypeScript 构建和受影响测试。

验收标准：

- [x] 相关单元测试通过。
- [x] Backend TypeScript 构建通过。
- [x] `git diff --check` 通过。
- [x] 未新增模型可见工具或放宽提交安全边界。

## 8. 总结

本次修复不增加 Agent 工具，而是在 `BrowserFillForm` 内为地区和纯点选日期建立真实状态机。成功标准从“命令执行成功”提升为“选择状态成立、必要确认完成且原字段值更新”。
