# 岗位库筛选与批量采集开发规划

> 状态：阶段一、阶段二已验收；阶段三自动验证及BOSS真实Agent验收通过，企业官网Agent入口待实测
> 更新日期：2026-10-18
> 开发顺序：1. 岗位筛选；2. 岗位页面采集与直接入库；3. Agent工具接入

## 1. 目标与范围

岗位采集改为直接写入岗位库；用户及Agent从岗位库按条件读取，不再通过最多10个临时候选逐个保存。

- 采集数量与读取数量独立设置。第一版采集数量默认100，允许1–1000；Agent列表读取默认20，最多100。数值集中配置，后续可调整。
- 支持现有BOSS直聘、北森、Moka及Hotjob适配器，本轮不开发新平台适配器。
- 使用应用维护的企业招聘来源名单，保留自定义企业入口。
- 已入库岗位属于持久化业务数据，不随会话删除、15分钟缓存过期或应用重启丢失。
- 采集入库不代表投递成功，不创建已投递记录，不要求绑定简历。
- 采集结果不由LLM逐个评分；模型只接收采集摘要，按需读取岗位。

现有采集实现及历史验收见[18-脚本化岗位采集方案](18-scripted-job-collection-design.md)。本规划的三个阶段完成后，替代其中的10候选上限、临时候选缓存及逐个引用保存流程；已有平台解析和ATS事实存储继续复用。

## 2. 统一数据与处理流程

```text
岗位页面 / Agent
  -> 关键词、渠道、目标数量、可选企业范围
  -> 后端冻结本次采集来源和条件
  -> 现有平台适配器采集、标准化
  -> 去重、检查岗位状态、批量写入岗位库
  -> 返回数量与来源结果摘要

岗位页面 / ReadJobs
  -> 岗位库共享查询逻辑
  -> 按条件筛选、排序、分页
  -> 返回当前需要的岗位
```

### 2.1 渠道与来源

- 用户渠道沿用 `boss_zhipin`、`company_website`、`other`；采集入口第一版只开放BOSS直聘和企业官网。
- `beisen`、`moka`、`hotjob` 是企业官网的适配平台，不替代用户渠道字段。
- 新采集岗位保留 `platform`、`sourceId`、原始岗位ID、招聘/申请URL、采集时间等可追溯信息。
- 旧岗位缺少平台或来源信息时保持未知，不按企业名称推测，不影响按既有渠道查询。
- 采集任务、ATS来源快照和用户岗位库分别保存；用户岗位库数据通过业务存储链路写入，不直接把事实库文件当页面数据源。

### 2.2 数量、去重与入库规则

- 目标数量表示本次满足关键词/采集条件、去重后的有效岗位总量，不是每个企业或每个查询分别达到该数量。
- 已在库中的有效岗位也计入本次找到的岗位数量；另行统计新增与已有数量，不把重复岗位冒充新增。界面使用“采集数量”，而非保证“新增数量”。
- 同一岗位在多个列表页、关键词或来源入口出现时只计一次。优先复用稳定平台身份；ATS使用平台、租户与原始岗位身份，BOSS使用平台岗位ID，不使用会话ID或采集批次构造重复岗位。
- 新岗位进入岗位库的未投递列表，不默认收藏；重复采集更新允许更新的来源事实，不重置投递状态、收藏、用户备注、简历关联或用户编辑字段。
- 用户主动删除的岗位不得在后台重复采集中静默复活；沿用逻辑删除记录处理，恢复另走明确操作。
- 源站明确已关闭的岗位不作为新采集有效岗位；状态未知时不猜测可投递，保留来源告警，不作为成功新增数量。
- UI与Agent复用同一入库服务和业务幂等键，重试及并发请求不产生重复记录。

## 3. 阶段一：岗位筛选

### 开发内容

1. 将岗位页现有条件面板接到真实岗位库查询，不再只保存采集条件。
2. 第一批必需筛选条件为渠道和关键词；已有城市、求职类型、薪资、经验、学历、公司规模条件接入有事实数据的字段。
3. 关键词以岗位名称、企业名称及JD做不区分大小写的文本匹配，不调用LLM。不同筛选维度用AND组合，同一维度多选用OR组合。
4. 未选择的条件不限制结果。字段缺失不猜测；开启对应条件时不把未知值当作满足条件。薪资只比较可明确解析的月薪，不随意换算日薪、年薪或面议。
5. 岗位库的全部、收藏、未投递和已投递视图都使用相同条件；保留其原有业务状态区分。
6. 使用后端共享查询、排序和分页，UI与后续Agent查询复用相同语义；避免每次把整个岗位库和全部JD发送给模型。
7. 支持清空条件、无结果提示和分页；筛选不修改岗位数据，不影响收藏、编辑、删除及投递记录。

### 验收标准

- [x] 渠道、关键词及其组合能筛选出预设的正确岗位；大小写、空关键词、无结果和未知字段有确定行为。
- [x] 条件对全部/收藏/未投递/已投递视图一致生效，清空后恢复原列表。
- [x] 后端分页总数与页面结果一致，翻页不重复、不遗漏；默认排序稳定。
- [x] 旧岗位、来源字段缺失的岗位仍可正常查看与管理。
- [x] 原收藏、删除、编辑和投递状态功能回归通过。

### 3.1 已实现接口与页面行为

- 页面通过 `WorkspaceBridge.QueryJobs` → `workspace:jobs-query` → 业务Worker的 `JobService.Query` → `JobRepository.Query` 查询，不在页面执行整库过滤与排序。
- 共享契约为 `packages/contracts/src/job-query.ts`；支持 `keyword`、`channels`、`cities`、`jobSeekingTypes`、`minMonthlySalary`、`experiences`、`educations`、`companySizes`、`view`、`sort`、`page`、`pageSize`。
- 界面沿用单选条件控件；共享查询接受多选数组，同维度OR、跨维度AND。缺省或空数组不限制，非法查询返回 `VALIDATION_ERROR`。
- 默认分数降序，随后按入库时间降序、ID升序；也可选择入库时间排序。页面每页20条，共享接口单页上限100条，返回当前页岗位、总数、实际页码、页大小和总页数。
- “已投递”包括已有已投递/笔试/面试/结束记录，或BOSS已确认打招呼的岗位；仅有收藏/待投递记录不算已投递。使用EXISTS判定，多份投递不重复岗位。
- 薪资按明确月薪的下限比较，支持K、万/月、元/月等写法；不换算年薪/日薪或面议。经验与公司规模按明确数字下限归入现有档位，学历按明确要求归类；缺失、不限或无法解析的值不满足对应已开启条件。
- 条件或视图变更回到第1页；清空筛选恢复默认条件及全部视图；删除末页最后一项时收敛到有效末页。岗位或投递变更后刷新查询，不因普通聊天消息追加而刷新。
- 岗位详情与编辑保留学历、公司规模；编辑时保留原岗位的来源信息等非表单字段。原有到期清理策略继续生效。
- 收藏/未投递/已投递合并到筛选栏的“岗位视图”菜单，保留“全部”选项。
- 排序按钮左侧提供批量删除入口；进入多选后使用空心/实心圆选择岗位，支持全选本页。翻页、排序保留已选项，切换条件或视图、退出多选清空选择；确认框冻结本次待删除ID及数量。
- 选择框的宽高、最小及最大尺寸统一为14px，覆盖全局输入框40px最小高度；未选、选中、半选、禁用和聚焦状态均保持圆形。全选控件按本页实际选择状态切换“全选本页”/“取消全选”，退出多选按钮显示“取消”。删除按钮仅显示现有Phosphor垃圾桶图标，悬停提示与无障碍名称包含已选数量。
- `WorkspaceBridge.DeleteJobs` → `workspace:jobs-delete-many` 批量逻辑删除，单次1–10000个ID，重复ID去重。业务Worker在同一事务中删除并记录审计；失败全部回滚，保留页面选择。已有投递记录和采集防重墓碑保留，成功后刷新分页与总数。
- 2026-10-18批量删除验证：新增4项SQLite/IPC测试通过，生产Worker往返覆盖批量删除、重复请求与删除后分页；全量Vitest667项通过、1项跳过，后端Node测试10项通过，完整构建及渲染层类型检查通过。圆形选择、多选操作位置及视图菜单待用户界面实测。
- 阶段一保留原指令预填入口；阶段二已替换为独立“采集岗位”面板，直接接入后端入库服务。Agent工具升级仍留在阶段三。

## 4. 阶段二：岗位页面采集与直接入库

### 4.1 企业来源名单

- 第一批从现有固定名单中选择已经验证可采集的入口。未知、不支持或仅有平台线索的来源不进入默认可采集清单。
- Hotjob首批使用已真实完整验证的中国中车社招和中科院力学所校招明确分类入口；不把多分类门户直接作为可采集入口。
- 来源记录至少包含：稳定 `sourceId`、企业名称、招聘URL、适配平台、招聘类别、启用状态、最近验证时间及最近错误。
- 同一企业可有多个招聘来源，例如社招和校招；企业选择与来源身份分开，不能因企业重名将不同入口合并。
- 内置清单随应用版本提供，用户本地的启停及选择不被更新覆盖。来源失败不导致清单静默删除。
- 页面预留“自定义企业”入口及独立本地来源存储结构，后续参数为企业名称与招聘URL；使用前须验证支持能力，不支持时明确展示原因。首版不要求完整来源管理页面，若配置能力尚未开放，入口明确显示待支持，不冒充已添加成功。
- 若补充企业名单，可通过网络查找官方招聘入口，再做来源验证；本轮不实现运行时自动搜索和扩充名单。
- 不把100家评测资格验收作为本轮前置门槛；默认名单逐入口核验。未知来源的调查结果继续保留在ATS评测文档。

### 4.2 页面操作

1. 岗位页新增“采集岗位”按钮，打开独立采集面板。
2. 面板包含关键词、渠道、目标数量、求职类型、学历要求；选择企业官网时可选择全部已启用企业或指定企业。BOSS保留城市查询及已登录浏览器前提。
3. 列表筛选条件和采集条件分开，修改列表筛选不隐式重新采集。“复制当前列表的可用条件”显式带入关键词、可采集渠道、求职类型、学历，以及BOSS支持的城市。
4. 首版单次任务选择一个渠道。企业官网可覆盖多个适配平台和企业，不沿用当前工具最多10个ATS来源的总量限制；来源分批由后端管理。
5. 执行时显示进度、已找到/新增/已有/失败数量，提供取消按钮；重复点击不创建相同的并发任务。
6. 完成或部分完成后显示摘要，刷新岗位库及未投递视图。刷新来自业务落盘结果，不能只修改前端临时数组或等待Agent对话结束。
7. 企业来源按当前名单顺序执行，到达总目标即结束；不保证每家企业都有岗位入库。未开始的来源显示“未执行”。

### 4.3 后端采集与入库

- 前端只通过类型化平台接口发起采集，Node网络、浏览器及业务写入留在后端；复用现有Worker业务存储及平台采集器。
- 根据来源清单解析企业入口；ATS不依赖浏览器登录，BOSS使用现有个人浏览器与授权，不使用隔离浏览器或新的CDP附着方案。
- 采集分段与续跑由后端完成；单个来源仍保持既有30s/30请求执行段、节流和出口约束。分段到限不等于整个任务终止，不要求Agent重复提交参数才能续跑。
- 遍历至目标数量、来源耗尽、明确访问/结构失败、取消或任务总期限。任务总期限与采集量匹配，在实现时集中设置并用真实采集耗时验证；不得只沿用10候选流程的超时配置，也不得无界执行。
- 到达目标数量仅结束本次入库选择；ATS事实快照未遍历完仍是partial，不能将关键词过滤结果或数量截断当作完整快照关闭其他岗位。
- 可确认且符合条件的岗位分批幂等入库。取消或后续来源失败不回滚此前已落盘批次；摘要明确实际新增和剩余情况，未完成来源不伪报成功。
- 已关闭、未知及stale来源状态不重置用户投递记录；沿用事实与业务状态分离的设计。
- 源站未提供的字段保持缺失，单条坏记录隔离，不以模型推测补造数据。
- BOSS检测到验证码、风险提示或登录失效时停止该来源并显示原因；ATS明确访问失败时记录错误，不绕过权限。
- 第一版不提供应用退出后的采集自动恢复或新定时采集配置；应用重启保留已入库岗位，未完成任务有明确中断状态。现有CronTask授权规则不变。

### 验收标准

- [x] 按关键词、渠道和目标数量采集，至少验证一次超过10个岗位的真实入库。
- [x] 北森、Moka、Hotjob各有已验证的内置入口；BOSS复用已登录个人浏览器完成简单采集。
- [x] 采集不调用LLM，不要求简历绑定；结束后岗位页及未投递列表立即与数据库一致。
- [x] 重复采集、重试和重复点击不产生重复岗位，已有收藏、备注及投递状态不被覆盖。
- [x] 取消、一个来源失败、无岗位及达不到目标数量时，任务及时结束且摘要与实际存储一致。
- [x] ATS多来源分批与分段续跑不依赖Agent；数量截断和partial快照不会误关闭岗位。
- [x] 应用重启可读回已入库岗位；任务中断不被显示为成功完成。

### 4.4 已实现接口与执行方式

- `WorkspaceBridge` 提供 `ListRecruitmentSources`、`SetRecruitmentSourceEnabled`、`StartJobCollection`、`GetJobCollectionTask`、`CancelJobCollection`；共享Schema位于 `packages/contracts/src/job-collection.ts`，数量默认100、范围1–1000。
- `JobLibraryCollectionService` 在后端独立执行任务，一次只运行一个采集任务。总期限为 `min(30分钟, 120秒 + 目标数量 × 5秒)`；ATS保留每段30秒/30请求限制，自动读取检查点续跑，连续三段无进展时停止该来源。
- 任务和来源启停保存于工作空间 `job-collection/state.json`，ATS事实保存于 `job-collection/ats-facts.json`；有效岗位每批最多25条，通过业务Worker事务写入岗位库。工作空间迁移同时复制采集记录和事实文件。
- 取消或超时后不再提交新批次，已经交给Worker的批次等待落盘后计数；重启将未完成任务标记为 `interrupted`，不自动续跑。来源后续失败时保留此前已确认的有效岗位，单条写入异常隔离并明确计数。
- 内置10个真实核验来源：北森4个、Moka4个、Hotjob2个。来源启停单独持久化，页面的全部/指定企业选择单独保存；自定义来源数据结构已预留，入口明确显示“待支持”。
- BOSS使用现有个人浏览器运行时，与Agent浏览器操作互斥；返回真实列表后，旧列表通过快照点击下一页，新列表通过正常键盘滚动加载，并等待新岗位身份出现。不依赖伪造分页URL。采集不发送消息、不投递、不调用LLM。
- 重复采集使用稳定平台身份去重，兼容旧岗位ID/URL；保留用户编辑字段、收藏、备注、投递和联系状态，不复活逻辑删除岗位。未知招聘类型等字段保持未知，不默认补成社招。
- 业务数据库迁移v15新增岗位采集身份/URL索引。页面按已落盘计数刷新查询，关闭弹窗不取消任务，重新进入岗位页可查看最新进度。
