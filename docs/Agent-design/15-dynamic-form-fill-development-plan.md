# Dynamic Form Fill：开发规划与进度

> 状态：已归档。当前 Agent 工具协议与执行流程见 `03-tools.md`；本文仅保留历史开发记录。

## 1. 背景与目标

真实企业招聘系统大量使用自定义下拉、日期选择器和所在地等多级级联控件。现有 `BrowserFillForm` 只能批量填写文本框、原生 `select` 和普通单选项，其他控件需要模型反复执行 `Click → Snapshot → Click`，在科大讯飞招聘页面上无法形成可用的自动填写体验。

本次调整保留一个模型可见入口：由 `BrowserFillForm` 负责完整的表单填写，`BrowserInspectForm` 只负责观察，`BrowserValidateForm` 只负责验证。Host 在工具内部执行有限的动态页面收敛，不新增 `BrowserFillSelect` 或 `BrowserFillCascader`。

## 2. 职责边界

```text
BrowserInspectForm
  -> 识别字段、控件类型和当前页面版本
BrowserFillForm
  -> 匹配档案/简历事实
  -> 批量填写稳定文本和原生控件
  -> 打开自定义下拉
  -> 等待并匹配真实选项
  -> 逐层推进级联菜单
  -> 页面变化后重新定位下一字段
BrowserValidateForm
  -> 报告剩余必填项和浏览器校验错误
```

`BrowserSelect` 和 `BrowserClick` 保留为未知站点控件的兜底能力，不是标准表单填写的主要路径。

## 3. 动态控件执行策略

### 3.1 控件识别

- `BrowserInspectForm` 从显式 label、`aria-labelledby`、相邻标签和表单项容器提取字段语义。
- 原生 `select` 继续使用选项值精确匹配。
- 对具有 `combobox`、`listbox`、`cascader`、`picker`、`select` 等语义的自定义触发器，补充 Host 内部标记和可访问名称。
- 自定义组件内部用于搜索的辅助输入框不作为独立表单字段返回。

### 3.2 收敛循环

`BrowserFillForm` 先执行不会改变 DOM 的稳定操作，再逐个处理动态控件：

1. 使用当前有效 ref 打开目标控件。
2. 获取新快照并等待候选项出现。
3. 对规范化后的候选项执行精确匹配；所在地允许去除“省、市、区、县”后的层级匹配。
4. 点击一层候选项后重新获取快照；仍有匹配的下一层时继续，最多三层。
5. 关闭当前控件后重新 Inspect，重新定位下一个动态字段，不复用 DOM 改变前的 ref。
6. 整个工具设置有限动作数和 deadline；无法可靠匹配时返回结构化跳过原因，不选择列表第一项。

页面加载和控件展开使用有限轮询；不对提交、上传、协议同意或消息发送做自动重试。

### 3.3 资料缺失

- 可由已有事实确定性推导的枚举值，由 Host 标准化后匹配。
- 求职偏好优先读取用户档案中的明确默认值。
- 缺少不可推导的必填事实时，返回紧凑的 `missingFields`，由 Agent 一次性询问用户。
- 可选且无来源的字段直接跳过。
- 无人值守任务遇到缺失必填硬事实时停在提交前，不随机选择。

本阶段实现已存档事实对应的自定义下拉和三级级联执行，以及缺失字段的结构化报告。Agent 汇总用户回答后，可在下一次 `BrowserFillForm` 中通过规范字段 `decisions` 补充；决策正文进入执行前即转为私有计划，并在 Trace 中脱敏。页面仍由 `pageRevision` 约束，因此第一版不再增加单独的恢复令牌。

### 3.4 真实页面恢复策略

科大讯飞实测暴露出日期弹层、固定底栏遮挡和重复 Inspect 污染页面的问题，执行器按以下规则恢复：

- Inspect 写入的可访问性语义只是一次快照期间的临时属性，快照前清理旧标记、快照后恢复原始 `aria-label` 和 `role`。
- 自定义触发器只扫描具有明确组件语义的节点，并按最近表单容器去重；不再遍历所有 `div`、`span`。
- 动态选项优先读取标准 ARIA/组件语义；对哈希类名门户组件，仅在控件展开后扫描当前可见的绝对或固定定位浮层，并临时把其中的真实可点击短文本节点暴露为候选项。候选项仍须与档案值精确或按所在地层级匹配，模型不能提供选择器。
- 国家区号等辅助下拉与手机输入框共享标签时，以文本输入框为主，不把电话号码误作下拉候选值。
- 日期字段进入独立日期编辑器流程，不使用普通文本选项或所在地级联匹配。
- 每个动态控件开始前和结束后都关闭残留弹层；失败路径同样执行收尾。
- 点击先使用原生 `scrollintoview`，只在工具明确返回 `covered by` 时进行有限的上下方向滚动重试。
- 单个字段失败转为 `skipped` 并继续下一字段；取消、超时和结果未知仍立即终止，不能被逐字段容错吞掉。
- 普通字段 Batch 失败时保守地标记该批字段为 `batch_failed`，不把无法确认的部分执行误报为成功。

### 3.5 科大讯飞页面专项修复

真实页面复盘确认问题不只是匹配词过少，而是字段定位与控件执行同时存在缺口：

- 快照中的可点击引用可能同时带有 `level` 等属性，引用解析不能假定 `[ref=...]` 独占一个属性块。
- 不再把继承得到的 `cursor: pointer` 当作节点自身可点击的证据；候选项应落到 `li`、按钮、ARIA 选项或自身注册点击行为的节点。
- 所在地级联区分“展开下一级的文字”和“选择当前项的单选图标”；选择图标后识别并点击“确定”，随后读取原字段显示文本验证提交结果。
- `agent-browser` 可能继续把已补语义的原生列表项回报为 `listitem`，匹配器需接受该真实角色，不能只接受 `option`。
- Phoenix 动态层不响应 `Escape` 和合成的根节点点击，并带有退出动画；每个字段结束后应通过本字段触发器关闭仍可见的弹层，等待动画结束后再处理下一字段。
- 日期操作与下拉操作一样执行后置值校验；只填写了弹层内部编辑器但原字段未更新时不得计为成功。
- 表单标签向上查找范围覆盖更深的自动完成组件包装层，使“学校名称”等字段不再退化为“请输入”。
- “项目职责/项目中职责”使用独立规范字段，不再与“项目描述”混用；投递档案模板同步提供该字段。
- 多段经历中的开始/结束时间按页面全局同名控件序号定位，避免每个章节都从第一个日期控件开始填写。
- 动态字段执行、弹层关闭和后置校验共用同一套规范字段别名与全局序号，避免“毕业时间”和“结束时间”分别计数造成校验错位。
- “在校学生/在读学生”等确定性枚举差异在 Host 内做窄范围同义归一化。

## 4. 不变量

- 模型不能提供 JavaScript、CSS selector、CLI 参数或 DOM 路径。
- Host 内部只操作已识别的表单控件和候选项，不读取密码。
- `BrowserFillForm` 不上传文件、不接受协议、不点击提交按钮、不导航。
- 下拉候选项必须由当前页面快照证明存在；无匹配即跳过。
- 档案和简历正文不进入工具参数、确认摘要和工具结果。
- 动态控件操作后废弃旧页面引用。

## 5. 开发部分与验收标准

### DF-01：Inspect 动态控件语义

- 识别普通输入、原生下拉和自定义下拉触发器。
- 过滤自定义组件内部辅助输入框。

验收标准：

- [x] 相邻文本标签能够映射到字段。
- [x] 自定义下拉作为一个字段返回，不把内部搜索框重复返回。
- [x] 密码和隐藏字段仍不返回。

### DF-02：Fill 动态控件收敛

- 稳定字段维持 JSON stdin Batch。
- 自定义下拉通过 Host 控制的“打开、快照、匹配、点击”执行。
- 级联菜单最多推进三层，每层重新读取候选项。

验收标准：

- [x] 已有档案值可以填写一个自定义下拉。
- [x] 已有所在地值可以连续选择省、市两层。
- [x] 所在地选择支持“展开文字、选择图标、确定按钮”的提交链路，并在结束后验证字段显示值。
- [x] 带 `level` 等附加属性的可点击快照引用仍能被识别。
- [x] 无 ARIA、动态哈希类名的门户浮层可以通过临时选项语义进入快照，且快照后恢复页面属性。
- [x] 同名复合控件不会把手机号码重复用于国家区号下拉。
- [x] 日期字段由独立弹层输入流程处理，结束后执行弹层收尾。
- [x] 无匹配候选项时不点击任意选项，并返回 `option_not_found`。
- [x] 固定页头或页尾遮挡时有限滚动重试；仍失败时返回 `element_covered` 并继续后续字段。
- [x] 工具不触发上传、协议或提交动作。
- [x] 多段经历的同名日期字段按全局顺序重新定位，不误填前一段经历。
- [x] 同一页面连续填写两个相似下拉时，前一弹层会先完成清理，不遮挡后一字段。
- [x] 连续日期字段即使 `Enter` 后弹层不自动关闭，也会在下一字段前完成收尾。

### DF-03：结果和缺失信息

- 结果区分 `filled`、`skipped` 和 `missingFields`。
- 不回显档案正文或填写值。

验收标准：

- [x] 缺少来源的必填字段以规范字段名和页面标签返回。
- [x] 工具结果和 Trace 不包含联系方式、证件号码等填写值。

### DF-04：简单验证

- 增加少量单元测试覆盖自定义下拉、两级级联和无候选项。
- 运行 Browser Runtime 相关测试与 Backend 构建。

验收标准：

- [x] 相关单元测试通过。
- [x] Backend TypeScript 构建通过。
- [x] `git diff --check` 通过。

## 7. 总结

动态下拉和级联菜单是表单填写能力的一部分，应由 `BrowserFillForm` 在 Host 内部完成。Harness 继续约束真实高风险外部动作，但不应迫使模型逐层操作普通表单控件。
