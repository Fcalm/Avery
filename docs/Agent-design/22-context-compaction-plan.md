# Avery Agent 压缩方案（精简版）

> 更新：2026-10-26；已接入实现，验证结果以本次开发回执为准。

## 1. 方案概括

**不再固定保留 5 轮。保留继续工作必需的信息，把已经发生的过程总结掉。**

压缩后，Agent 主要看到：

```text
完整 system 和有效 Skill
当前任务要求、关键事实、未完成事项
仍需使用的浏览器页面信息
历史摘要
最近必要的原始对话和完整工具步骤
当前用户输入
```

`/compact [instructions]` 先让 Agent 结合上下文，把用户意图翻译成具体的压缩要求，再调用一次 `CompactContext`。沿用当前 Provider、模型、思考开关和强度，工具选择保持 `auto`。摘要模型只接收整理后的要求、业务历史和程序保护的状态，不直接接收原始 instructions。程序负责检查和安全替换。

## 2. 浏览器任务没做完，snapshot 怎么处理？

要分清三种信息：

| 信息 | 处理方式 |
| --- | --- |
| 任务进度，例如教育经历已填、工作经历未填、暂不提交 | 必须保留；不能靠页面快照代替 |
| 继续操作需要的页面结构、字段值、元素引用和页面版本 | 保留最近一次完整观察；需要时重新观察 |
| 过去的点击、重复快照、已经失效的页面结构 | 总结操作结果，原始记录留在本地 |

**任务未完成，不代表每一次 snapshot 都要留在模型窗口中。**需要留下的是任务进度和继续操作所需的最近页面信息。

对于“全量快照 + 多次增量”，不能删掉全量、只留下最后一次增量。建议这样处理：

1. 依赖链较小时，可以整体保留。
2. 依赖链过大或不完整时，整链移入摘要；保留任务进度、差异和必要证据。首版不生成合并快照。
3. 压缩后操作页面前，程序要求重新调用 `BrowserSnapshot`，该次观察返回全量；页面版本和引用检查继续生效。

“最近页面观察”只代表最后观察时的状态，不代表页面此刻没变。页面重载、引用失效或版本不符时，操作前重新观察。当前实现的引用检查继续生效。

如果快照本身就很大，先保留任务进度、重要页面证据和原始记录引用，把旧结构移出窗口；后续需要操作时再读取。若新读取的内容仍放不下，应提示缩小处理范围，不能假装几句摘要足以支持点击。

例子：正在填写教育经历时，保留学校、学历、起止日期、未匹配字段、页面与档案差异，以及“尚未提交”；不必保留前面十几次展开下拉框的全部快照。已经消失的错误提示或提交回执需单独保留，不能指望重读页面找回。

## 3. 复杂任务撑满上下文怎么办？

**取消“保留最近 5 轮”的规则，改按内容大小分配空间。**不承诺至少保留几轮完整工具轨迹。

保留顺序：

1. system、有效 Skill、当前用户要求、禁止事项和待确认状态。
2. 当前未完成任务的进度、关键事实、操作回执及必要页面信息。
3. 最近仍有用的原始对话和工具结果。
4. 其余历史总结为摘要。

一轮用户消息可能产生几十次工具调用，因此**同一轮内部也允许压缩**。比如任务有 30 个步骤，前 27 个已完成步骤可以总结，保留最近必要步骤及剩余计划。

一个工具调用批次与它的所有结果必须配对；工具正在运行或结果未齐时不能从中间切开。待执行或待确认的动作不补写成已完成。

每次模型调用前都检查实际要发送的内容，包括 system、工具定义、历史和附件，并预留回复空间。沿用设置中的触发阈值；压缩后重新检查，腾出明显余量，避免刚压完就再次触发。具体空间分配通过后续测试确定，本报告不再堆叠多组未经验证的参数。

若当前用户原文、必要规则或必须保留的页面内容本身已经放不下，说明问题并要求缩小范围，不静默截断。

## 4. `/compact` 能否让 Agent 调用压缩工具？

**Agent 充当翻译官：理解用户意图，结合任务优化和补充，再用工具提交压缩要求。**程序负责保护不能丢的状态。

正常流程：

```text
用户：/compact 重点保留教育经历和未匹配字段
  ↓
Agent 结合当前上下文，翻译成具体压缩要求
  ↓
提示词要求单次调用 CompactContext，程序校验次数与参数
  ↓
摘要模型根据整理后的要求、业务历史和受保护状态总结
  ↓
检查内容和大小，成功后切换上下文
```

Agent 传给工具的 `compressionInstructions` 应讲清楚：

- 当前正在做什么、已经完成什么。
- 后续准备做什么。
- 必须保留的事实、限制和相关消息／工具结果引用。
- 哪些内容需要详细保留，哪些过程可以简化。

例如用户说“保留教育经历”，Agent 应整理为“保留学校、学历、起止日期、与档案不一致的字段、尚未解决的问题及后续核对步骤；简化重复点选过程；继续保留尚未提交的状态”。只能补充上下文有依据的内容，不能更换用户目标或遗漏明确限制。

**原始 instructions 只供翻译 Agent 理解和本地记录使用，不作为另一份要求附送给摘要模型。**压缩命令单独保存，不混入供摘要使用的业务历史；重做摘要时也遵守这一边界。整理后的要求用于指导取舍，事实仍依据原始业务记录，不能把 Agent 的建议当成确认或授权。

`/compact` 的翻译请求只提供 `CompactContext`，仅通过提示词要求调用，保持 `tool_choice: auto`，不发送 `required` 或指定工具参数。返回后只接受一次有效调用；零次、多次、工具名或参数不合法均明确失败，原历史和草稿保留，不自动补一轮工具调用。

翻译和摘要均沿用用户当前思考设置，不临时降档。此前含噪上下文实验中，思考开启、提示词要求调用的三次样本均成功单次调用，但这不构成调用保证；运行时仍严格验证。

切换上下文安排在这次工具调用完成、结果已记录之后。程序随后直接结束压缩流程，不再让 Agent 用旧上下文继续输出一轮回复，也不自动执行“下一步”。压缩命令与工具回执单独记为活动，不算新的业务对话轮次。

这一方式通常比直接摘要多一次 Agent 调用。手动命令使用上述翻译流程；自动压缩由程序按默认规则和已有任务状态触发，不额外请求一轮翻译，也不等待 Agent 自觉调用。

翻译请求计入规则、唯一工具定义和规范化历史；超出安全预算时明确失败，保留上下文与草稿，不能跳过翻译而直传原始 instructions。摘要请求允许对超大旧历史分块，最多八次摘要请求；取消和失败均不切换历史。

## 5. 摘要结构和提示词

参考 Claude Code 的“工作交接”思路：摘要应让后续 Agent 知道做到哪里、还缺什么，并避免重复犯错。Avery 不照搬代码文件、代码片段等专用栏目，建议采用下面的简短结构；无内容的栏目可以省略。

| 栏目 | Avery 需要保留的内容 |
| --- | --- |
| 目标与约束 | 当前要完成什么，最新修正、禁止事项和用户限制 |
| 关键事实与资料 | 必要的简历、档案、岗位信息及来源，保留关键数值和版本 |
| 进度与当前状态 | 已完成和未完成事项，已验证的结果，待确认或结果未知的动作 |
| 浏览器任务 | 当前页面、已填和未匹配字段、差异与必要观察引用；完整页面结构按第 2 节单独保留 |
| 问题与纠正 | 尚未解决的问题、用户纠正，以及值得避免的失败做法 |
| 下一步 | 接下来需要做什么、缺少什么；不构成执行授权 |

摘要提示词草案：

```text
请为后续继续工作的 Agent 写一份简洁交接摘要。
根据整理后的压缩要求和业务历史，决定信息的详略。
保留目标、最新修正、关键事实、未完成事项与后续需要的证据。
明确区分已完成、未完成、待确认和结果未知，不把计划写成事实。
简化重复过程，保留影响下一步的失败原因和纠正。
按上表组织；没有依据的内容不要补写，不输出隐藏推理或执行工具。
```

还要分别验证“翻译是否忠实”和“摘要是否保真”：同一份历史换不同关注重点时，细节应随重点变化，但未完成任务和必要限制不能消失。

## 6. 用户怎么使用？

- `/compact`：Agent 按当前任务整理压缩要求。
- `/compact 重点保留……`：Agent 翻译并补充用户重点，其他未完成任务和必要约束仍保留。
- 选择命令后可以继续输入，按发送才执行；不把整条命令当成普通业务问题。
- 执行时在对话中显示整理意图和“压缩上下文”工具过程；工具详情包含整理后的要求与阶段，完成后保留估算结果和摘要正文，失败或取消保留过程及草稿。
- 首版手动入口只在会话空闲时可用；运行中或等待确认时保留草稿并提示。任务尚未完成并不等于会话正在执行，两者分开判断。自动压缩可在运行中的安全步骤边界进行。

关注重点默认只作用于本次压缩，不写入长期偏好。如果用户后来换了重点，可以从本会话保留的原始历史重新总结；已有历史若早已丢失原文，就明确说明无法完整找回。可见命令、过程和摘要保存为对话投影，不作为新的业务历史发给摘要模型。Trace 同时记录消息、Provider 请求、工具回执与具体错误原因。

## 7. 必须守住的规则

- **原始记录保留在本地。**压缩只改变模型看到的内容，不删除聊天、工具结果或业务数据。
- **失败不丢历史。**取消、摘要失败、检查失败或保存失败，都继续使用旧版本；禁止先删最早几轮再重试。
- **状态不被摘要改写。**未确认不变已确认，结果未知不变成功，工具成功回执不直接等于业务成功。
- **权限不变。**Agent 的保留建议、网页内容和摘要都不能扩大权限；关键状态由程序从现有记录读取并保护。
- **Provider 请求合法。**修正已发现的思考参数遗漏，保留业务调用所需的连续性字段；摘要支持取消、超时和输出限长。
- **一次只处理一个会话版本。**压缩不与发送、重载或其他压缩同时提交；晚到结果不能覆盖新内容。

语义摘要不能保证所有细节无损。对学历、日期、ID、禁止事项、待确认内容等重点检查，普通细节通过原始记录保留回查能力。

## 8. 实施顺序与验收

1. 补足原始历史保存；取消固定五轮和有损重试；支持每次调用前检查、同轮完整步骤压缩及压缩后复查。
2. 处理浏览器任务进度、快照依赖和全量恢复；接通 `CompactContext` 与 `/compact [instructions]`。
3. 用复杂求职任务验证：原始 instructions 不直达摘要模型，Agent 翻译不曲解意图；压缩后能接着完成工作，重点事实不丢，确认状态不变，取消／失败可恢复；再测实际 Token 和耗时。

工具说明、Schema、Provider 适配、提示词、命令面板和 ADR 随实现同步。原文按会话和摘要 ID 异步归档，归档成功后再提交新视图；删除会话同时清理对应归档。

自动压缩在每次业务模型请求前检查；失败时暂停并保留浏览器任务页。手动命令只处理压缩，不自动继续业务任务。摘要参考保留尾部中的最新用户纠正，避免将旧值误写成当前事实。
