# OfferGet Version Roadmap

> 文档状态：规划基线
> 更新日期：2026-08-19
> 依据：`docs/PRD.md`、`docs/ARCHITECTURE.md`、`docs/Agent-design/` 与灾后重建计划

## 1. 规划原则

- 三个版本顺序交付；上一版本未通过数据、安全和回归门禁时，不进入下一版本。
- 每个版本均包含开发、单元/集成测试、文档、发布验证和缺陷修复。
- 第三方平台变化、审核等待和 Provider 故障不应成为降低安全门禁的理由。

## 2. Version 0.2.0 — Rebuild and Local Core

**目标**：把灾后可运行工程恢复为可维护、可重复构建的本地产品基线，稳定现有手动求职闭环。

**开发重点**：

- 将 Desktop Main、Preload 和 Backend 编译产物逐步重建为 TypeScript，并保持现有契约行为。
- 固化 workspace、共享契约、IPC 校验、统一错误码和前端事实源刷新机制。
- 补齐数据库迁移、revision 冲突、操作补偿、附件引用、备份和损坏库恢复。
- 稳定会话独立 Usage、项目环境恢复、真实 Provider Usage 与本地 Trace 对账。
- 完成干净安装、构建、Windows 打包、视觉回归、恢复演练和缺陷修复。

**交付范围**：

- 首次引导、档案、现有简历、求职助手、岗位库、投递管理、设置和开发者工具可稳定使用。
- Main 保持薄壳；业务和 Agent 运行在 Backend，数据库 I/O 不阻塞 Renderer/Main。
- API Key 只进入短期内存和 `safeStorage`；日志、Trace 和诊断内容完成脱敏。
- 岗位仍以手动录入为主，投递仍以人工执行和手动跟踪为主。

**发布门禁**：

- 新环境执行 `npm ci`、构建、测试和打包成功，安装包图标与运行入口正确。
- 旧工作空间升级、迁移失败回滚、最近备份恢复和未知 Schema 拒绝写入全部通过。
- 历史会话进入后立即恢复各自的 Usage 与项目环境，迟到事件不会污染其他会话。
- 1280×800 与 1024×680 下关键控件无遮挡、拖动不畸变，核心流程可键盘操作。
- 未恢复的原始源码或无法验证项必须写入发布报告，不以编译产物冒充源码。

**本版本不包含**：结构化简历正式迁移、URL 岗位提取、浏览器辅助投递、外挂视觉服务。

## 3. Version 0.3.0 — Structured Resume and Assisted Application

**目标**：建立结构化简历与场景化 Agent，并交付“自动填写、人工最终提交”的辅助投递闭环。

**开发重点**：

- 定义简历模块 Schema，完成旧简历迁移、PDF/Word 导入、模块编辑、预览、版本和导出。
- 实现简历优化、岗位定制、项目提炼和投递辅助场景，绑定 Prompt、工具白名单与权限快照。
- 支持从用户提供的 URL 提取岗位信息，经预览确认后写入岗位库。
- 建立首个受支持页面适配器，完成字段识别、自动填写、附件上传、暂停和用户接管。
- 补齐 Agent、项目环境、结构化编辑、辅助投递的安全测试与发布回归。

**交付范围**：

- 简历由稳定模块和条目组成；Agent 使用增删改排命令，常规流程禁止整篇文本覆盖。
- “无需确认”允许 Agent 自动保存新版本，但保留差异、来源和上一版本，不扩大其他权限。
- 项目环境按会话只读授权，遵守 `.gitignore` 和敏感文件拒绝规则，并展示可读取清单。
- 辅助投递自动完成可确认字段与材料，最终提交前固定展示岗位、简历版本和关键答案。
- 验证码、未知必填项、敏感问题、登录失效和页面不兼容均暂停，不尝试绕过。

**发布门禁**：

- 结构化导入无法识别的字段必须由用户确认；Agent 无依据编造事实的验收次数为 0。
- 用户与 Agent 并发编辑通过同一锁和 revision 校验，冲突不得静默覆盖。
- 项目路径逃逸、敏感文件读取和未授权工具调用的安全测试结果为 0。
- 受支持页面标准字段填写准确率不低于 90%，重复提交为 0，最终提交始终由用户确认。
- 投递成功后固定关联实际简历版本、关键答案、时间和结果凭证。

**本版本不包含**：无需最终确认的全自动提交、多平台批量投递、外挂视觉与完整面试助手。

## 4. Version 1.0.0 — Automated Application GA

**目标**：在可审计和可停止的前提下开放受控全自动投递，补齐视觉辅助并达到正式发布质量。

**开发重点**：

- 实现平台/批次级全自动授权、过滤规则、每日上限、置信度门禁、幂等和状态对账。
- 扩展至少两个经过验收的申请流程适配器，并建立页面变化检测与降级机制。
- 接入用户自备 Key 的外挂多模态模型，完成逐次授权、最小图片发送和不确定性标记。
- 提供基于 JD、简历和档案的基础面试准备清单，不改变简历与投递事实。
- 完成自动化长稳、隐私安全、性能、安装升级、恢复、发布候选和缺陷修复。

**交付范围**：

- 辅助投递继续作为默认；全自动模式必须对具体平台或投递批次单独显式启用。
- 自动任务保存岗位、规则、表单来源、置信度、简历版本、步骤、回执与最终状态。
- 未知字段、敏感答案、验证码、二次认证、测评、协议、费用和状态未知时强制暂停。
- 全局停止立即阻止新页面操作和提交；已发生副作用必须完成对账，不能盲目重试。
- 无视觉能力的文本模型可调用单独配置的视觉服务；未配置时明确不可用，不回退本地 OCR。
- 开发者工具提供脱敏 Trace 与真实 Usage 对账，不上传遥测、崩溃报告或用户业务数据。

**发布门禁**：

- 基准场景的投递流程完成率不低于 80%，标准字段填写准确率不低于 90%。
- 重复提交、超限提交、未经授权提交、状态未知自动重试和验证码绕过均为 0。
- 未经授权的图片上传、项目读取、凭据泄漏和工具越权均为 0。
- 基准设备冷启动至可交互首页 P95 不超过 5 秒，本地常规交互 P95 不超过 200 毫秒。
- 安装、升级、卸载保留数据、备份恢复、自动化中断恢复和全局停止演练全部通过。

**正式版后续**：根据真实平台维护成本评估更多适配器、深度面试训练与可选的隐私云同步；不承诺绕过平台限制。

## 5. 版本依赖与调整规则

- `0.3.0` 依赖 `0.2.0` 的 TypeScript 运行时、迁移恢复、权限和 Trace 基线。
- `1.0.0` 依赖 `0.3.0` 的结构化简历、人工确认投递和完整审计链，不允许跳过中间门禁。
- 第三方页面变化只调整适配器范围或排期，不得降低验证码、敏感问题、幂等和用户授权规则。
- 单个版本范围发生重大变化时，应重新评估并更新本文；禁止通过删除测试或安全门禁压缩工作量。
