# 校招汇总采集与岗位读取

## 使用入口

岗位页的“采集岗位”面板选择“校招信息汇总”，或在工作场景调用：

```json
{
  "channel": "campus_aggregator",
  "graduationYear": 2027,
  "city": "上海",
  "keyword": "产品",
  "targetCount": 20
}
```

可选 `company`、`batch`；`refresh: true` 重新校验来源和岗位缓存。`city` 也支持企业官网采集，入库岗位必须有对应官网地点。校招汇总默认只采集官网明确标注的校招或实习；类型未知时不凭公告标签推测。

`keywordScope`默认`all`，匹配名称、企业和JD；明确查找某类岗位时使用`title`，只匹配岗位名称。

来源为 <https://campus.sma-wiki.cn/campus/campus_recruit.html?channel=bz>。公告先在本地按公司、届别、批次、城市及关键词筛选，再采集支持的 ATS 入口。微信公众号、未支持、受限或无效入口跳过，不创建招聘线索，不作为岗位保存。回执提供公告数量、匹配数、跳过原因和来源链接。

第三方届别和批次仅用于发现入口。岗位名称、地点、正文等来自 ATS；不复制第三方岗位摘要、企业评价或截止日期。任职资格以官网岗位说明为准。

采集前自动清除明确属于2026及以前的届别或春招/补招批次（如`26届补招`、`26春招`），并从本地公告缓存移除；不指定届别也生效。混合门户中名称明确标注旧届别的官网岗位不入库。跨届包含2027及以后、开放范围、未知届别及仅有发布日期的信息保留；`2026年秋招（2027届）`不会被当作旧届别。回执统计清理数量和原因。当前清理范围固定截至2026，后续按已确认规则扩展，不随公历换年自动扩大；不批量删除用户已有岗位。该清理不等于逐岗位核实全部毕业资格。

## 缓存与失败

- 公告缓存位于工作空间 `job-collection/campus-cache.json`，15 分钟内直接复用。超时校验清单，复用已下载的版本化分片；刷新使用 ETag / Last-Modified 条件请求。
- 首次下载或全部分片换版时可能需要全量下载。缓存不是逐条变更接口。
- 下载分片逐个保存；中断后继续未下载部分。未完成的版本不会提供伪完整筛选结果，来源失败不会缓存为空列表。
- ATS 完整且有效的近期事实可复用 6 小时；刷新绕过事实缓存。15 分钟内的分段缓存可先筛选，数量不足再继续原检查点，不作为完整集合。
- 采集取消、超时或失败保留已经入库的岗位，并报告实际数量。
- 遇到代理 Fake-IP，使用固定 Cloudflare HTTPS DNS 服务核实公网地址，再将地址固定到 HTTPS 连接；核实失败、私网和混合解析仍拒绝。不修改系统网络配置，不携带登录 Cookie。

## 飞书 ATS

支持识别飞书招聘域名及声明招聘元数据的自定义站点。公开岗位详情入口保留原始岗位 ID；单岗位读取不表示企业岗位全部遍历完成。

列表优先按官网HTTP协议读取。HTTP拒绝不直接推断为私有接口；返回SOURCE_BROWSER_REQUIRED。采集面板勾选“允许浏览器辅助采集飞书岗位”，或CollectJobs传`browserFallback: true`，可使用当前选定浏览器读取标准`/{portal}/position/list`页面，由网站正常加载原生关键词搜索结果。后台公开详情最多3个并发，入库顺序串行。不生成签名、不导出登录Cookie。

多企业任务先处理通常可后台读取的来源，再处理飞书来源。一个CollectJobs调用由脚本逐个处理候选企业，达到目标停止，回执coverage说明已检查、失败、未执行与浏览器辅助来源数量。首次扫描成本仍随企业数量增加，不承诺覆盖所有企业或找到全部岗位。

浏览器列表按企业、关键词、页码缓存15分钟；详情缓存6小时，正文采集时间不因缓存复用而更新。关键词范围为title时，列表中已知的非匹配岗位在详情请求前跳过。缓存每个企业段统一落盘，最多128个列表页、2000个详情且正文总量不超过800万字符。

浏览器串行导航，每个企业辅助阶段最多60秒且受整个任务期限约束。失败保留已写入岗位并继续其他来源；登录、验证或详情不可读时报告未完成原因。后台辅助采集需要Cron导航授权，与Agent和测评共用浏览器占用检查。仅支持已识别的飞书招聘域名；自定义域名仍使用HTTP适配器。

浏览器搜索完成仅表示当前关键词结果读完，不作为企业全部岗位事实快照。单岗位公开详情验证不表示所有飞书租户都支持采集。

## ReadJobs

| detailLevel | 内容 |
| --- | --- |
| `count` | 仅匹配数量，不返回岗位列表 |
| `brief` | 默认模式，岗位 ID、公司、名称、城市、薪资、学历、经验等；不带 JD 或 URL |
| `summary` | 简表加 URL、投递状态和最多 300 字符 JD |
| `detail` | 必须指定 jobId，单次 JD 最多 8000 字符；省略 detailLevel 且有 jobId 时默认此模式 |

默认每页 20 项，最多 100 项，整个回执限制 12000 字符，因此实际条数可能小于请求数量。使用 `nextCursor` 续读时保持筛选条件、detailLevel 和 maxResults；详情续读保持 jobId。详情提供 jdOffset / jdTotalChars，正文变化后旧游标拒绝拼接。

推荐先 count，再收窄数据库筛选，读取一页 brief，选中后再读 summary 或 detail。不要让模型遍历整库自行过滤。列表翻页期间岗位发生增删或排序变化时，应重新查询。
