# 岗位采集浏览器

## 行为

- 岗位页“采集岗位”的 BOSS 采集及企业官网、校招采集中的浏览器回退，使用设置页“使用的浏览器”。
- 每次占用浏览器时读取已保存的选择，支持 Chrome、Edge、ego；运行中的任务保持原浏览器，新任务使用最新设置。
- Chrome/Edge 未连接时在所选浏览器打开配对页；未安装或未完成扩展接入时报告对应错误，不借用其他浏览器的在线连接。
- ego 使用原生任务工作区：首次浏览器操作创建独立空间，同次采集复用，采集结束后按自动关闭偏好关闭或交还用户；无需 Avery 扩展。连接检测只握手，不创建空间。
- 纯 HTTP/API 采集不启动浏览器。

## 修复记录（2026-11-06）

- 复现条件：一个浏览器的 Avery 扩展已在线，在设置中选择另一个浏览器后开始浏览器采集。
- 根因：采集入口已同步设置，但扩展 Bridge 共用握手、长轮询和命令队列；已有在线连接会使新浏览器的连接检查提前返回。
- 修复点：按浏览器隔离配对凭据、握手、Worker 代次、命令、结果、清理和诊断；运行时及检测脚本显式读取所选浏览器状态。
- 兼容行为：旧配对没有浏览器归属，升级后不再接收其命令轮询；首次检测或采集会打开所选浏览器重新配对，无需更新扩展文件。

## 防回归验证

- `tests/unit/backend/job-collection-browser-settings.test.ts`：真实 Host、Runtime、Bridge 链路连续切换三个浏览器，任务期间保存设置、互斥及失败后释放。
- `tests/unit/backend/browser-extension-bridge.test.ts`：旧浏览器在线时连接新浏览器，双方同时在线且 Worker ID 相同，命令与结果隔离，清理归属，切回旧浏览器，以及拒绝无归属旧凭据。
- 浏览器运行时、ego、BOSS 采集、飞书回退及岗位库采集相关测试保持通过。
- 实机验收：重启开发版，在设置中依次选择 Chrome、Edge、ego 后采集 BOSS 岗位；确认页面出现在所选浏览器，并在其他浏览器保持在线时重复验证。此项由用户操作验证。
