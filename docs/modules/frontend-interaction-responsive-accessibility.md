# 前端交互、响应式布局与可访问性规范

> 状态：0.2.0 实施规范
> 适用范围：Renderer（`src/`）全部页面；视觉规则以 `docs/DESIGN.md` 为准，产品验收以 `docs/PRD.md` 为准。

## 1. 目标与边界

本规范固定 Avery 桌面端的窗口档位、交互反馈、键盘路径和可访问性下限。Renderer 只经 `shared/platform` 调用 Bridge，不因布局或可访问性需求直接访问 Electron、Node.js 或文件系统。

发布验收窗口为 **1280×800** 与 **1024×680**。小于 1024px 的 CSS 降级样式可以保留，以支持窗口缩小过程，但不构成 0.2.0 工作台完整功能承诺。

## 2. 响应式布局

| 范围 | 规则 |
| --- | --- |
| 应用外壳 | 默认侧栏 224px；可拖动范围 192–320px；收起后 40px。非助手页面主内容最小宽 800px，助手主区最小宽 480px。 |
| 1280×800 | 展示完整侧栏、Letterhead、主页面与固定输入区；所有关键操作应在无需横向滚动时可见。 |
| 1024×680 | 仍保留可读侧栏与主工作区；右侧简历面板切换为覆盖式抽屉；主页面不得产生横向页面溢出。 |
| 小于 620px | 隐藏侧栏、收紧页面边距；表单双列改为单列，Modal/Drawer 全宽。此为降级体验，非发布门禁。 |
| 页面滚动 | `page-container`、消息列表和抽屉内容独立滚动；固定顶栏、输入区和抽屉操作栏不得随内容滚走。 |

### 2.1 助手输入区

- 使用 `ResizeObserver` 依据输入区实际可用宽度判断紧凑态，阈值为 640px；禁止仅按窗口宽度判断。
- 紧凑态将权限、场景和模型控件压缩为 36×36 图标按钮；可见文本可隐藏，但 `aria-label`、`title` 和弹出菜单语义必须保留。
- 发送、停止、上传与项目环境入口不得因压缩而消失、重叠或变形。
- 会话 Usage 使用等宽数字：真实 Provider 值显示百分比；缺失显示“未知”；新会话显示“—”。

### 2.2 拖拽与面板

- 侧栏仅可在 192–320px 内调整；拖拽期间以 `is-resizing-sidebar` 禁止文本选择，结束时必须移除该状态和事件监听器。
- 助手右侧简历面板在宽屏可调整，在 1179px 以下改为覆盖式抽屉并提供遮罩关闭入口；窄屏不保留不可用的拖拽把手。
- 每次页面、窗口宽度或面板状态变化后，关键主操作（保存、发送、停止、确认、暂停）必须仍在视口内。

## 3. 交互状态

所有关键流程应提供 loading、empty、success、error、conflict 或 recovery 中适用的状态；不能只依赖静态按钮是否可见。

| 场景 | 必须行为 |
| --- | --- |
| 数据加载 | 显示本地工作空间加载态，避免白屏。 |
| 后端恢复/只读 | 显示恢复门禁和可执行的恢复入口，禁止把可写操作伪装成成功。 |
| Mutation | 按一次用户意图保留稳定幂等键；自动重试复用，settle 后释放。 |
| 冲突 | 显示可理解的冲突提示并刷新事实源，禁止静默覆盖。 |
| 长任务 | 明确运行、暂停、等待输入、等待确认、取消、完成和失败状态；停止操作持续可见。 |
| Modal/Drawer | 打开后焦点进入容器；Escape 关闭（不可关闭的确认场景除外）；关闭后焦点回到触发控件。 |

## 4. 键盘与可访问性

- 原生 `button`、`input`、`textarea`、`select` 优先；图标按钮必须提供中文 `aria-label`，纯装饰图标使用 `aria-hidden`。
- 所有键盘可达控件保留可见焦点态。复合输入区可以将焦点环绘制在 `.composer:focus-within`，但不得让键盘用户失去当前位置。
- 表单错误通过 `aria-invalid`、`aria-describedby` 与 `role="alert"` 关联；不要只用颜色传达错误。
- Dialog 使用语义角色与名称，焦点必须困在弹层内；Tab/Shift+Tab、Enter、Space、Escape 是必测路径。
- 尊重 `prefers-reduced-motion: reduce`：非必要动画与滚动动效应停止或缩短至可忽略时长。
- 文字、焦点环、状态色和按钮对比度遵循 DESIGN 的最低要求；点击热区不小于 32×32px。

## 5. 回归矩阵与证据

每次影响布局、输入区、导航、弹层或焦点的变更至少执行：

1. 1280×800、1024×680 各主页面无横向溢出，关键操作未出界。
2. 助手输入区在普通与紧凑态都保留上传、权限、场景、模型和发送/停止入口。
3. 侧栏拖拽边界、收起/展开、右侧简历面板打开/关闭不造成内容畸变。
4. 键盘验证：导航 Enter/Space、Modal/Drawer Tab 焦点循环、Escape 关闭与焦点回归。
5. `prefers-reduced-motion`、加载/错误/恢复/空态可读且不依赖颜色作为唯一信息。

已完成的双分辨率六主页面证据见 `docs/rebuild/F-04-FRONTEND-REGRESSION-2026-08-20.md`。真实前台键盘焦点、Modal/Drawer 焦点循环与拖拽仍需在交互式 Electron E2E 中持续执行，不能用后台截图替代。

## 6. 维护规则

- 新增页面先使用 Design token、间距与圆角刻度，再添加响应式规则；不得用独立硬编码色值或尺寸绕过系统。
- 新增可点击图标、抽屉、弹窗或快捷键必须同步更新本规范的回归矩阵。
- 修改窗口下限、侧栏宽度、输入区紧凑阈值或焦点策略时，必须同时更新 `DESIGN.md`、本规范和对应自动化证据。
