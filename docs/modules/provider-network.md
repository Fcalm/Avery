# 模型与额度查询的网络连接

## 2026-11-09 问题记录

最近六次失败涉及 MiMo 和 DeepSeek，Trace 的底层错误为 `ENOTFOUND`，另有 `UND_ERR_CONNECT_TIMEOUT`。这些请求在域名解析或连接阶段失败，没有供应商 HTTP 响应，不能据此判断为额度耗尽或密钥失效。

故障记录仍使用 1 秒、2 秒间隔和三次请求，说明记录产生时的运行进程尚未加载后续调整的 2 秒、4 秒、16 秒重连策略。

本机启用了 `127.0.0.1:7897` 系统代理。原 Provider 使用 Node 全局 fetch，模型补全、摘要、模型列表、连通性检查和 DeepSeek / GLM 额度查询都没有接入系统代理。MiMo 额度查询另由桌面隔离登录会话完成，原本已使用 Chromium 网络栈。

当前无凭据连接复查时，模型与余额端点已重新返回 HTTP 响应；过程中 MiMo 控制台曾出现连接重置。日志证明发生了 DNS / 连接故障，无法单凭这些记录还原故障期间每条代理规则或上游状态。

## 修复

- Backend Utility Process 使用 Electron `net.fetch`，经宿主端口注入 Provider；常规对话、摘要、配置检查、API 额度查询以及评估执行 / Judge 统一跟随系统代理。
- 不替换全局 fetch，不改变 ATS、浏览器采集等独立网络边界，不修改操作系统 DNS、代理地址或登录资料。
- 模型传输省略 Cookie、不缓存、拒绝重定向，保留调用方的认证头、请求体、流和取消信号，并绕过自定义协议处理器。
- 将 Chromium 的建连错误与响应 body 断流错误转换为稳定诊断码；内容长度不匹配、半截 chunk、HTTP/2 中断仍可恢复，证书错误不反复重试。
- 错误提示区分域名解析、系统代理、连接超时与一般中断，不显示密钥或上游正文。保留 2 秒、4 秒、16 秒等待和立即取消行为，不重放已执行工具。

网络能力依据 [Electron net 文档](https://www.electronjs.org/docs/latest/api/net/)及本机 Electron 43.3.0 类型定义；默认模块通过窄端口接收传输，不直接依赖 Electron。

## 验证

独立、无窗口的 Electron Utility Process 使用正式编译后的传输适配器与本地隔离代理：同一 `.invalid` 地址在 Node 直连下返回 `ENOTFOUND`，经 Chromium 代理返回 200 并完整接收 SSE。主动中断响应 body 后，正式恢复逻辑能重试并读到完整答复。代理配置仅作用于该临时会话，不改动系统设置。
