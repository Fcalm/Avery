# 采集入库与关键词匹配

## 入库行为

- BOSS 岗位通过关键词、求职类型、学历筛选后，逐条等待数据库入库确认并保存进度，再继续访问下一个岗位。
- 超时、取消或来源故障保留已经入库的结果；取消时等待已提交写入完成计数，停止提交新岗位。
- 企业 ATS 继续按现有批次和来源分段入库。
- 入库数量仍只统计确认保存的新增和已有岗位；保留去重、已删除岗位不恢复、用户编辑保护及坏记录隔离规则。

## 关键词行为

- 比较双方统一全半角、忽略大小写，并移除空白、标点、符号和不可见分隔字符；保留文字与数字。
- `ai产品经理`、`AI 产品经理`、`ＡＩ·产品－经理` 按相同关键词匹配。
- 仍按原顺序执行包含匹配，不补充同义词或忽略其他文字；仅含符号的关键词与空关键词一致。
- 标题范围只检查标题；全文范围分别检查标题、公司、正文，不跨字段拼接关键词。
- 只规范化筛选比较，保留原始岗位内容。飞书列表和校招公告前置筛选使用同一规则。

## 修复记录（2026-11-06）

- 复现条件：BOSS 目标 20 个，检查 51 个，43 个被关键词排除，其余 8 个暂存；220 秒期限到达。
- 根因：不足一个批次的结果等到采集结束才入库，超时分支停止新写入，导致内存结果未保存；字面包含匹配还会排除空格和符号不同的标题。
- 修复点：BOSS 筛选通过即入库；各前置筛选与入库筛选统一关键词规则。
- 自动验证：复现任务改为超时后保留 8 个；覆盖运行中已落盘、取消等待在途写入、跨渠道标题/全文匹配、原始内容保留及飞书/校招前置筛选。
- 实机验证：重启开发版后以原条件重新采集，查看运行中入库计数与超时后的保留结果；由用户操作反馈。
