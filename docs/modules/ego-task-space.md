# ego lite 任务工作区

## 网申工作区续接

- 复现条件：在 Ego Lite 表单填写过程中断开桥接、切换对话或重启 Avery。原表单可能仍然开着，但后续 Run 无法定位原任务空间。
- 原因：旧桥接只在握手时校验 `spaceId`；新进程每次创建新空间，且传输断开时会尝试清理原空间。
- 工作场景实际使用 Ego Lite 时，Host 固定注入 `ego-workspace`，并启用 `BrowserWorkspace`。页面工具沿用原有参数。新任务由后端读取浏览器设置，续接使用原任务绑定的浏览器。
- Avery 持久保存当前工作任务的原生空间身份和最后确认的任务页。可恢复中断或切换对话时保留空间。续接核对空间归属和原页，并清空旧快照引用。原页已关闭时返回明确错误。
- 临时交接和完成后保留使用不同的原生操作。用户在会话内确认继续后，Host 恢复原空间。关闭时保留归属不明的标签页。网申待用户投递时可保留工作区。
- 回归覆盖固定注入、传输中断、用户新增标签页时的清理保护，以及真实 Ego 中表单填写、交接、Host 重启和原页恢复。真实浏览器用例需先执行 `npm run build:packages`，再以 `AVERY_TEST_LIVE_EGO=1` 运行 `tests/integration/agent/ego-workspace.test.ts`。

## 修复方向（2026-11-09，修改阶段记录）

- 复现条件：设置选择 ego lite，执行 Agent 网页任务或岗位采集，只在已有工作区增加标签页。
- 根因：`AgentBrowserRuntime` 把三个引擎统一送到 Avery 扩展；现有 `EgoBrowserRuntimeProvider` 和 `EgoBrowserBootstrap` 没有接入正式组合流程，原生创建工作区代码无法执行。
- 修复：ego 使用原生空间驱动；状态检测不创建空间，首个任务操作创建一个 `Avery ego-<任务 ID>` 工作区，同任务复用；Chrome/Edge 保留现有扩展路径。设置的一键接入改为启动 ego 并检测原生服务。
- 收尾：保留现有自动关闭偏好；开启时只关闭本任务空间，关闭时解除调试并将空间交还用户；用户接管、空间丢失和创建失败均明确停止，不回退个人页面。
- 验证：运行时分流、连接检测、同任务复用、跨任务隔离、关闭/保留、取消与错误归属；复跑原生 Bootstrap、扩展和岗位采集回归，再运行包构建与类型检查。

## 完成与验证

- 已完成正式 Runtime 的 ego 原生分流，以及 Main、preload、客户端和设置页的一键接入链路。连接状态使用原生服务事实，不再以其他浏览器的扩展在线状态代替。
- 工作区丢失、用户接管或原生连接断开后，当前任务停止；后续工具调用不能自动创建替代空间。只有结束任务后才能创建新空间。创建连接取消或超时会释放驱动，不自动重建第二个空间。
- 本机 ego lite 的正式后端实测通过：只访问随机端口的本机静态页面，两次导航及一次快照保持同一个 `ego-f3ebca2e-5de3-4e66-877a-f09febc82703` 任务；原生关闭回执确认清理两个任务标签页，未访问外部网站、个人页面或用户档案。
- 原生 Bootstrap 的关闭/保留、空间所有权、外部目标拒绝、用户接管和未知清理回执继续由隔离单测覆盖。
- 正式采集入口通过真实 AgentHost/Runtime、原生 Provider 夹具验证：检测不创建空间，同次采集复用，两次采集各自创建并释放，不调用扩展连接。
- 浏览器与桌面接入、采集、Host 恢复和测评相关共 16 个文件、343 项测试通过，包含追加的取消/创建超时回归；后端另有 14 项 Node 测试通过。
- `npm run build:packages`、前端 TypeScript 检查、Renderer 构建通过；保留既有大 chunk 提示。

## 重启后的人工验收

1. 设置选择 ego lite，点击“一键接入”和“检测状态”；应显示原生连接结果，不出现扩展安装步骤，也不因检测生成空工作区。
2. 发起 Agent 网页任务或岗位采集，确认出现 `Avery ego-...` 工作区；任务内跳转、快照及后续操作留在同一工作区。
3. 分别检查自动关闭开启/关闭：任务结束后只关闭本任务空间，或保留页面并交还用户；再次发起任务创建新工作区。
4. 切回 Chrome/Edge 后仍使用所选浏览器的扩展任务页；用户接管、删除工作区或连接中断后，原任务不自行换新工作区继续。

按 `src/AGENTS.md` 未运行设置界面的自动化复现或冒烟；本机实测针对后端原生适配链路，设置按钮的界面效果留待用户重启实测。
