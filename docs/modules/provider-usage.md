# 用户菜单供应商用量

- 用户菜单展示所有已配置凭据的供应商；打开菜单或点击刷新时读取，关闭后不轮询。
- 菜单与头像入口合计不超过应用高度的 60%，供应商列表独立滚动，底部设置操作保持可见。
- 按量付费卡片显示账户余额和账单入口。
- 订阅卡片支持多个额度窗口、剩余百分比和重置时间。
- DeepSeek 使用官方 `GET https://api.deepseek.com/user/balance`。
- GLM 国内站使用 `GET https://open.bigmodel.cn/api/biz/account/query-customer-account-report`，通过 API Key 的 Bearer 鉴权读取 `data.availableBalance`。`totalSpendAmount` 是累计消费，不作为本月消费展示。该控制台接口未承诺公开 API 的稳定性。
- MiMo 使用 `GET https://platform.xiaomimimo.com/api/v1/balance`，依赖控制台登录态，不发送模型 API Key。未登录时卡片提供“登录授权”，过期后提供“重新登录”。
- 登录在独立的官方窗口完成，使用专用持久会话；登录窗口没有 preload，不开放 Node.js、任意导航或系统权限。只在余额校验成功后自动关闭窗口。
- MiMo 的会话型 Cookie 另经系统安全存储加密保存在 `mimo-account-session.enc`，重启后恢复到专用分区；不写业务数据库、不返回渲染层、不改变供应商原有过期时间。连续 30 天未成功使用后，本地授权不再恢复；服务端拒绝授权时要求重新登录。
- “断开授权”会中止在途查询、关闭登录窗口并清除专用会话和加密授权文件；模型 API Key、系统浏览器登录与其它应用数据不受影响。
- 自定义供应商未配置账户查询能力时，仅显示不支持，不发送账户请求。
- “查看账单”通过系统浏览器打开固定的供应商控制台页面。

## 订阅展示测试

PowerShell 中运行 `$env:VITE_PROVIDER_USAGE_DEMO='1'` 后启动 `npm run dev`，用户菜单会加入名为“订阅演示”的隔离卡片，包含 5 小时和月度两个额度窗口。测试结束后执行 `Remove-Item Env:VITE_PROVIDER_USAGE_DEMO`，并重启开发服务器。该样本不写入供应商配置或数据库，生产构建不包含这张卡片。

## 人工检查

重启桌面应用后检查：菜单内查询与刷新、部分供应商失败、账单入口、深浅色主题，以及缩放窗口后的 60% 高度边界和列表滚动。开启开发测试开关时，同时检查订阅额度、进度条和重置时间。

MiMo 额外检查：首次登录、取消登录、授权过期、断开授权后重新登录，以及退出重启后会话恢复。真实账户的余额和登录流程需人工验证，不以无凭据的接口探测或单元测试替代。
