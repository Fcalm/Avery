# 桌面自动更新

- 更新源固定为 `https://github.com/Fcalm/Avery/releases`，包含预发布版本，禁止降级。
- Windows 安装版启动 15 秒后检查，此后每 6 小时检查。常规设置中的“检查更新”使用同一服务；重复请求合并，手动检查最短间隔 30 秒。
- “自动下载更新”开启时后台下载，关闭时只提醒。更改偏好不会取消已经开始的下载。
- 提醒位于侧栏用户菜单上方，显示新版本、下载进度或重启安装入口。可收起并重新展开，同一版本记住收起状态，新版本重新提醒。
- 安装只在用户点击“重启安装”并确认后进行。普通退出不会安装，不自动中断 Agent 任务。安装前应保存编辑内容并结束任务。
- 开发模式、后台 CronRunner 和冒烟实例不检查或安装更新。检查或下载失败不得显示“已是最新”。

## 发布文件

1. 发布新版前提升根 `package.json` 的版本，运行构建与相关测试。
2. `npm run pack:win` 仅构建，不上传 GitHub。
3. 将同一次构建生成的 `Avery-Setup-<version>-x64.exe`、对应 `.exe.blockmap` 和 `latest.yml` 一起上传到该版本的 GitHub Release，再发布 Release。
4. 不手工修改 `latest.yml` 的版本、文件名或校验值，不混用不同构建的文件。使用带预发布后缀的版本时，同时上传构建生成的对应通道 YAML。
5. 发布后使用较旧的、已内置更新器的安装版验证检查、下载、取消安装和确认安装。

未内置更新器的历史版本需要先手动安装一次包含本功能的新版；仅补充 GitHub 发布文件不能让旧客户端获得更新能力。更新文件缺失时客户端报告检查失败。

## IPC

`averyUpdates` 仅提供 `GetState`、`Check`、`Download`、`Install` 和 `OnStateChange`。命令无参数，Main 校验主窗口主 frame、调用频率和状态，前端校验状态 Schema。更新源、缓存路径与安装命令不暴露给网页或 Agent 工具。
