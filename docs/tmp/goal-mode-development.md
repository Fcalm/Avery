# Goal 模式开发记录（临时）

更新时间：2026-11-13。分支：`codex/goal-mode`。

## 开发方案

1. 模型设置固定为次级模型与高级模型。每档引用已配置的供应商与模型。后端保存两档及版本，Goal 使用次级模型审核。尚未配置时，Goal 使用本轮执行模型审核。
2. 对话通过 `/goal <目标>` 启动。每个会话保留一个活动目标。Goal 的原始目标、用户约束、审核次数、模型配置、进度和退出原因由后端保存。
3. 在 Agent 内核准备结束 Run 时发起独立审核。输入为用户目标、本轮答复、相关工具结果和回执。后端验证结构化结论及引用，审核模型可返回达成、继续、需用户介入或无法完成。
4. 需要继续时向同一执行 Agent 注入内部反馈。已有工具轮数、页面状态和浏览器任务继续沿用。人工确认、缺少资料和浏览器接管沿用已有等待路径。用户恢复后先核对最新页面与已完成动作。
5. 后端按 Goal 累计时间、审核轮次和 Token，检测连续重复缺口。审核不可用、证据缺失且无法补齐、预算耗尽时保存未验收进度。取消、切换目标或重启后校验状态，防止迟到审核结果驱动执行。

## 验证计划

- 从生产桌面路由读写档次。已配置时审核请求使用次级模型，未配置时使用执行模型。历史三档文件读取时保留最低和最高档。
- 从本地读取供应商配置或恢复会话时无模型列表请求。显式获取时访问供应商接口，重新进入设置保留已删除的模型。
- 在真实 Provider 传输端注入固定的 SSE 响应，驱动完整 Run，验证首次回答缺交付物时审核退回，执行 Agent 根据反馈补齐，最终只产生一个完成事件。
- 验证审核无工具权限、证据引用校验、等待确认后从原 Run 恢复、取消与审核失败不会触发下一轮。
- 使用浏览器替身与持久化回执检查续轮和恢复行为，覆盖禁止重放已完成动作。
- 运行相关后端测试、前端类型检查和构建。真实模型的判断效果需用案例单独验证。

## 已实现细节

2026-11-17 的 Goal 钩子与续跑更新见 [Goal 模式工程参考](../Agent-design/24-goal-engineering-reference.md#实现记录)。

- **入口。** 设置 → 模型配置 → 模型档次，选择次级模型和高级模型后保存。单模型能力覆盖仍走原配置。普通对话和 Goal 执行都使用对话中选择的模型。
- **启动与恢复。** 直接输入 `/goal <目标>`，或从命令菜单选择「目标模式」后输入目标。等待人工确认或问答时使用现有确认卡。审核等待补充时，发送补充内容会回到原目标。也可点「继续目标」或使用 `/goal continue <补充说明>`。等待期间用 `/chat <消息>` 发送独立的普通消息。继续先审核现有证据，再决定下一步。执行中的停止按钮取消整次 Goal。重启后的非交互中断需要用户显式继续。
- **模型与数据。** 启动时冻结审核模型身份、接口地址和能力快照。审核使用低思考强度请求，由现有适配器映射为供应商支持的参数。审核请求无工具，最多请求 1,200 输出 Token，输入受该模型上下文和 16,000 Token 总预算约束。只发送目标、近期用户补充、候选答复及投影后的证据。次级模型如果属于另一家供应商，这部分内容会由该供应商处理。
- **审核与收尾。** 主模型返回不含工具调用的答复后，先保存候选结果，再触发 Stop hook。审核通过后才发完成事件，未通过的答复显示为过程。模型必须引用已有证据，标为外部状态的通过项至少需要一条有效工具证据或回执。续跑和交付审核的结论保存在对话过程。审核反馈带内部来源，只在本目标的执行上下文中使用。验收条目由审核模型从用户目标与限制推导，条目覆盖是否充分仍需用真实案例检查。
- **预算。** 最多 6 次审核，累计活跃运行 3 小时，累计已上报的主模型及审核用量 2,000 万 Token。显式继续为续跑及交付各预留一次审核。Token 按请求结算，可能在一次已发出的请求中越过阈值，后端随后禁止继续执行新工具。缺少 usage 另行计数。连续三次交付审核发现相同缺口且无证据变化时暂停。单次审核最多 3 分钟，受 Goal 剩余时间约束。
- **写操作。** 同一 Goal 内完全相同的幂等提案可以复用回执，人工确认仍绑定原动作与页面版本。跨 Run 恢复浏览器时必须重新观察页面。状态未知或账本只有 started 的写操作需要用户先核对，Goal 继续入口不会自动重试。

## 验证记录

- 11 个 Goal 集成用例经过生产 Host、Kernel、Provider 请求序列化和持久化存储。SSE 响应可控，浏览器使用替身。覆盖最低档模型路由、未达标反馈、唯一完成事件、前序候选结果的展示边界、无效和伪造证据、人工确认、重启、超预算、取消、重复缺口与幂等回执。

- 档次的供应商可用性在本地按已保存凭据及模型身份校验。该检查不证明远程模型仍有额度或一定遵循审核格式。

## 模型配置回归修复

- 开发版打开模型档次时，IPC 路由指向的 `AgentRunService` 缺少读写转发。补齐两个方法，经真实路由验证空配置读取、保存、回读及 Goal 审核。
- 首次初始化后，本地模型列表由用户维护。进入或关闭设置、恢复会话时仅读取本地配置。供应商模型列表通过「获取模型列表」同步，公开能力目录通过「更新目录并匹配」更新。
- 旧三档文件保留最低档和最高档及当前 revision，用户保存时写入两档。无档次配置时使用本轮执行模型发起独立审核，后续继续目标沿用启动时的审核配置。
- 两个档次可引用同一模型。已移除下拉选项互斥和后端唯一性校验，桌面路由集成用例覆盖同模型保存与回读。
- 43 项直接回归和 14 项后端 Node 检查通过。包构建、Renderer 类型检查及构建通过。扩大回归后 405 项通过、1 项跳过、1 项失败。失败的归档迁移用例构造 v18 数据库时保留了 v20 的迁移记录，导致迁移历史不连续。

## 真实模型验收

| 用例 | 预期 | 观察项 |
|---|---|---|
| 简历已满足完整结构与真实经历约束 | 审核一次后达成 | 审核请求模型、最终内容、误拦 |
| 简历漏掉用户指定的经历，或出现无依据指标 | 退回并指出缺口 | 是否补对内容，是否误判已完成 |
| 用户要求保存简历，但执行者只有草稿 | 缺少写入回执，目标不得达成 | 真实版本、回执与最终状态 |
| 独立网申页面有未填写字段 | 要求回读并补齐，停在授权边界 | 页面最终值、未重复动作、人工确认 |
| 最低档不可用或返回无效结论 | 暂停并保留已执行结果 | 错误提示、未误报达成、未更换审核档 |

开发版手工验证可先在未配置档次的工作区运行一个只在对话中交付的简历目标，查看 Trace 中 `goal_review` 的模型是否与本轮执行模型一致。再在模型配置保存次级与高级模型，重开设置确认回读，启动新目标并核对审核使用次级模型。删除一个供应商模型后重开设置，确认它只在手动同步时重新出现。记录误判、续跑次数、审核输入和输出 Token、缓存命中及端到端延迟。当前未发出实际供应商请求，也未在真实招聘网站执行写操作。
