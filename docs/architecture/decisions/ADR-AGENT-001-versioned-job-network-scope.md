# ADR-AGENT-001：岗位网络能力按版本启用

> 状态：已接受
>
> 决策日期：2026-08-20
>
> 决策依据：[A-02 产品裁决](../../rebuild/A-02-PM-DECISION-2026-08-20.md)
>
> 实现授权：仅允许在 A-03 中收窄 0.2.0 生产工具清单；不得实现网络能力

## 上下文

此前 Agent 设计允许默认场景自主调用 `SearchJobs` 和 `ReadUrl`，但 PRD 与版本路线图仍以手动岗位闭环为主。当前 Agent 还存在白名单执行校验、取消迟到事件、原子快照、工具取消、日志脱敏和待确认草稿等安全缺口。在这些门禁关闭前增加网络能力，会同时扩大 SSRF、隐私、站点条款、取消和审计风险。

## 决策

1. 0.2.0 不开放岗位联网发现或 URL 提取。`SearchJobs`、`ReadUrl` 均为 `enabled: false`，不得进入生产 Tool Registry、ScenarioSnapshot、Prompt 或执行分发。
2. 0.3.0 只评估“用户明确 URL → 受限 `ReadUrl` → 预览 → 用户确认后入库”。URL 必须来自当前用户消息；Agent 不得搜索、猜测、补全或沿页面链接扩展来源。
3. `ReadUrl` 必须逐次校验重定向，拒绝本机、内网、文件协议、凭据、Cookie、登录态和非预期内容类型，并限制响应体、时间、重定向与下载量。
4. `SearchJobs` 在 0.3.0 仍禁用。未来有界按需发现不形成版本承诺，启用前必须另行更新 PRD、路线图与 ADR。
5. 后台搜索、周期监控、无界翻页、跨来源持续聚合和“扫描全网”永久属于非目标。
6. 网络结果只是不可信数据。0.3.0 的岗位入库通过独立窄写入边界、冻结提案、revision 与业务幂等键完成，不隐藏在读取工具内。

## 替代方案

- **0.2.0 直接开放自主岗位发现**：交付快，但会在安全门禁未关闭时扩大攻击面，否决。
- **0.2.0 仅开放用户 URL**：范围较小，但仍偏离本版本恢复本地基线的目标，延后到 0.3.0。
- **永远禁止所有岗位网络能力**：边界最简单，但失去未来可控提升效率的空间，不采用。
- **提供任意 HTTP/浏览器工具**：无法形成最小权限和稳定审计，永久否决。

## 影响

正面影响：

- 0.2.0 工具面更小，A-03 可集中关闭既有安全缺口。
- 0.3.0 网络范围可独立威胁建模、测试和回退。
- Prompt、工具白名单和产品版本获得同一事实源。

负面影响：

- 0.2.0 用户仍需手动录入岗位。
- `SearchJobs` 草案不能用于产品承诺或排期估算。
- 0.3.0 需要新增网络端口、预览确认和合规测试成本。

## 迁移

1. 从 0.2.0 默认场景、Prompt 和工具返回列表移除 `SearchJobs`、`ReadUrl`。
2. Schema 可保留为 `disabled_draft`，但增加静态测试证明不会注册或执行。
3. 0.3.0 另建版本化场景变更，先完成安全 fixture 和发布门禁，再启用 `ReadUrl`。
4. 未来评估 `SearchJobs` 时创建新 ADR，不直接修改本 ADR 的语义。

## 回退

若 0.3.0 `ReadUrl` 出现安全、稳定性或合规问题，立即将其恢复为 `enabled: false`，新 Run 回到手动录入；保留既有岗位数据和审计记录，不回滚用户已确认入库的业务实体。回退不允许临时替换为任意 HTTP 或浏览器能力。
