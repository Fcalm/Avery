# ADR-AGENT-003：Context 预算、压缩阈值与 Run 上限

> 状态：已接受
>
> 决策日期：2026-08-20；压缩规则修订：2026-10-26
>
> 实现授权：已授权；场景轮数与 Runtime Reminder 于 2026-08-22 开始实施

## 上下文

过晚压缩会让未知工具结果和输出挤爆上下文；按消息条数裁剪会切断 assistant tool call 与 tool result；无界模型循环会掩盖错误。另一方面，过早或按字节硬切会丢失用户约束、待确认标签、revision 和未完成工作。

## 决策

1. 使用 Provider 保存的压缩阈值，输入预算为 `contextLimit - min(8192, contextLimit * 10%)`。每次业务模型调用前估算完整输入，压缩后复核空间。
2. 取消固定保留五轮。按预算保留最新用户原文、有效 Skill、最新提醒与近期步骤；工具调用及全部结果是不可拆分批次，允许同一复杂用户轮次内压缩早期步骤。浏览器增量链完整保留或整链总结，压缩后先重新观察。
3. 单 Run 模型子轮按场景配置：默认场景 30，投递场景占位 100。最后一轮由 Runtime Reminder 要求模型停止发起工具并收束；若仍返回工具调用，Kernel 拒绝执行并暂停。不得创建新 Run 自动绕过。
4. Prompt 安全片段、当前工具定义、待确认交互、`【待确认】` 标签、未完成工作、关键 ID/revision 和 Tool Receipt 不得被摘要改变。
5. Provider Usage 只使用 API 返回值；缺失时为 `unavailable`。本地估算仅用于单请求上下文预判，并使用不同字段；累计 input tokens 不设 Run 级硬预算。
6. 同类压缩验证错误最多纠正 1 次；仍无法安全收缩时进入 `paused`，不静默删除历史。
7. `/compact [instructions]` 由 Agent 结合上下文优化要求后，提示词要求单次 `CompactContext` 调用；沿用当前 Provider、模型和思考设置，工具选择保持 auto，不强制选择。原始后缀只供翻译与本地记录，不直传摘要模型。
8. 原文先异步归档，再持久化切换摘要视图。取消或失败保留旧历史；自动压缩失败暂停并保留浏览器任务页，手动命令不自动继续业务任务。

## 替代方案

- **固定保留五轮**：单轮复杂任务也可能占满上下文，改用预算与完整工具批次。
- **固定保留最后 40 条消息**：会切断工具链，否决。
- **只依赖 Provider 超限错误**：恢复体验差且可能浪费调用，否决。
- **无上限子轮**：无法给模型明确的收束边界，否决；场景上限本身可以随产品需要调整。
- **把估算 Usage 展示成真实值**：破坏事实来源，否决。

## 影响

正面影响：

- 压缩时机、测试 fixture 和 UI 预算口径一致。
- 工具调用组和待确认状态可恢复。
- 模型循环和压缩重试具有确定上限。

负面影响：

- 长材料任务可能更早触发摘要调用。
- 某些超长用户输入仍需暂停并要求缩小范围。
- 需要分别维护预算估算与真实 Usage 账本。

## 迁移

1. 阈值从 Provider 统一读取，默认/投递场景模型子轮上限继续沿用场景快照。
2. 压缩改用预算和完整工具批次；原有完整用户轮次读取接口保留兼容。
3. 覆盖单轮长任务、工具配对、浏览器依赖、取消与存储失败、最新纠正和 Usage 事实源。
4. Trace 记录压缩前后估算、摘要 ID；完整来源保存在本地会话归档。

## 回退

需调整压缩预算时同步更新文档与回归；不得回退为静默删除历史、拆开工具批次或伪造 Usage。保留原文归档、权限和场景轮数上限不变量。
