# ADR-BACKEND-003：工作空间跨文件/数据库操作采用 Saga

> 状态：已接受  
> 决策日期：2026-08-21  
> 相关实现：`apps/backend/src/electron/backend/services/workspace-operation-service.ts`

## 上下文

附件导入、配置保存、备份和工作空间复制同时修改文件系统与 Business DB，无法获得跨文件系统/SQLite 的分布式事务。进程崩溃若只依赖 try/catch，会留下文件已写入但 DB 未提交，或 DB 已提交但文件缺失的半完成状态。

## 决策

1. 每次跨边界操作先在 `workspace_operations` 创建版本化 Saga 记录，再推进 `prepared`、`file_written`、`db_committed`、`completed` 状态。
2. 失败标记为 `rollback_required` 或 `failed`；启动恢复按操作类型、版本、校验和与受控路径执行补偿或完成提交。
3. 未知操作类型或未来版本不可猜测恢复，工作空间进入只读/阻断写入状态。
4. 清理、回滚和恢复只允许处理经过路径、真实路径、普通文件/目录与内容哈希验证的受控目标。

## 替代方案

- **两阶段提交/分布式事务**：文件系统不支持参与者协议，复杂度高且无法解决外部副作用，否决。
- **只记录错误后要求人工清理**：数据完整性和可恢复性不足，否决。
- **先写数据库再写文件**：仍会产生反向半完成状态，不采用。

## 影响

正面：崩溃后可枚举、审计并确定性恢复；未知版本宁可只读。负面：每项新跨边界操作必须定义状态机、校验和补偿逻辑，开发成本增加。

## 迁移

1. 新的跨文件/数据库写入先注册操作类型与 payload schema，再实现成功、失败和重启 fixture。
2. 为操作版本升级添加显式恢复策略；不得覆盖旧 payload 解释。
3. 迁移前创建备份，恢复结果写入无正文审计事件。

## 回退

恢复失败或操作版本未知时保持 `WORKSPACE_BUSY`/恢复只读，而非删除证据。用户可从已验证备份恢复；临时目录和派生文件仅在路径/哈希验证通过后清理。
