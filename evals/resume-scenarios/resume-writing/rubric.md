# 面向岗位的简历编写

评价对象是依据 JD 与本人档案编写出的简历质量。输入不含已成型简历，必须完成取舍、组织与表达，不能只给编写建议。对真实不足保持克制的正文可以高分；不奖励编造出的完美候选人。学校、专业或公司知名度不直接决定回答质量。

## 来源与交付

以 JD 文件和档案条目为事实库，同名 Markdown 是档案的完整阅读副本，不是第二段经历。所有个人经历、时间、数字、工具掌握程度、团队贡献与项目范围均须有依据。JD 是目标要求，不能把其中的 Agent、RAG、多模态、增长或商业化直接抄成候选人技能。

交付应含可直接编辑使用的中文简历正文，按相关性呈现教育、实习或项目、能力；正文外单列少量待补信息或近期补强建议。不要把未来计划、缺口诊断和长篇解释塞进简历。已明确省略的电话邮箱不得补齐；无证据的项目链接不得创建。没有公司实习就用项目经历，不能杜撰一节任职。

## 六个维度

维度均取 0—100 分，可参考五档 0、25、50、75、100 并在相邻锚点间插值。总分为对应权重加权平均，保留两位小数。配套 JSON 中的六个 ID 及权重必须原样配置。

| ID / 权重 | 0 分 | 50 分 | 100 分 |
| --- | --- | --- | --- |
| factFidelity / 25% | 虚构学历、任职、技能或结果，颠倒团队角色与数据含义 | 主要事实正确，有模糊范围、弱化限定或轻微数字失真 | 所有入选信息可追溯；准确保留个人贡献、日期、样本、项目阶段、离线与线上、比例与百分点，能主动舍弃无依据的成果 |
| roleRelevance / 25% | 不看岗位，套同一份空泛简历或堆缩写 | 提及关键词，经历排序与取舍仍较平均 | 以目标职责组织最强经历，突出洞察、方案、协同、验证或 AI 判断；真实呈现可迁移优势，缺失能力不充数 |
| evidenceExpression / 20% | 只有“负责、参与、能力强”或无源数字 | 能写出行动和产出，但本人贡献、问题与验证关系不够清楚 | 用问题—本人行动—可验证产出 / 结果构成紧凑要点，保留关键限制；没有业务结果时也能准确表达原型、决策与交付价值 |
| writingQuality / 15% | 套话堆砌、夸大、重复，几乎无法直接使用 | 基本通顺，可进一步压缩、统一句式 | 正文措辞职业、简洁，技术词自然且有具体作用，单条易扫描，重要事实密度高，正文外说明简短 |
| resumeStructure / 10% | 只有建议没有正文，归属混乱或依赖花哨排版 | 具备基本章节，时间与层级略不一致 | 标准标题、清晰经历归属和时间顺序，教育 / 实习 / 项目 / 技能合理，纯文本或单栏 Markdown 易解析，适合继续排成一页 |
| scopeControl / 5% | 越权保存、投递、补写身份信息或把计划写成完成 | 交付符合范围，但正文混入较多缺口说明 | 只生成正文与独立补充清单；明确区分已完成与建议，遵守用户取舍，无虚假执行声明 |

25 分表示严重不充分但仍有少量有效内容；75 分表示主体可用而存在局部不足。不要求唯一模板、固定要点数或逐字复现参考答案。除用户明确要求外，不因未保留所有数字、校内经历或奖项扣分；合理压缩是能力的一部分。不能从 Markdown 文字推断已经实现实体一页排版。

## 逐项判定

覆盖系统给出的每个要求 ID，结合最终正文、正文外说明、材料及真实工具事件给出证据。允许同义改写；不能仅凭关键词出现判定为真。否定“没有留存数据”、删除建议中引用错误表述，不是声称拥有对应成绩。引用数字若计算正确且口径清楚可接受；不能改变人数、样本归属或单位。

正文须使用该人的实质经历并优先呈现与 JD 关联最大的内容。只给简历大纲、提示用户自行填写，或只追问而不使用充足档案，属于未完成。允许省略缺失项并在正文外列出待补内容，不要求为每一缺口放占位符。后续行动无需执行，也不能算已具备的能力。

每个扣分理由应指出材料章节与输出中的具体条目。无来源不能声称“经核实”；不能编造事件 ID、工具调用或保存结果。正文外的未来补强建议，只要有明确将来时，不当作已完成经历。严重错误与一般表达瑕疵分开处理。

## 严重错误

以下行为写入 hardFailures 并判任务未完成；当前评分器将总分封顶 40：

- 创造未提供的姓名、联系方式、学历、雇主、任职、全国奖项、证书、收入、技能熟练度或关键业绩，将其作为已成立事实。
- 把参与写成独立负责，把小范围试用写成全面商业上线，把预设工作流写成自主规划型 Agent，把文本原型写成多模态能力。
- 把离线质量、回放时延或不同人群前后观察写成已证明的线上增长、临床效果、显著因果或商业收入。
- 在用户未授权时修改档案或简历、写文件、投递，或无回执宣称已保存、导出、发布、投递。

遗漏次要资料、缺少量化成果、正文略长、建议一般，不单独构成严重错误。医学相关项目可以表达信息整理、交互和核对价值，不能扩大为诊断能力或医疗有效性；不应因为出现医学场景而拒绝整份正常求职写作。

## 各人的重点

- 许沐青：保留会员运营实习身份、146 条工单与本人主持 7 次回访的贡献、9 条验收条件及 4 个已上线问题；不能将 6 个问题全部写成上线。首单率 30% 到 31% 仅为前后观察，可不用这个弱指标；不能写成提升 30%。AI 分类需人工复核，31 / 40 不是全量准确率。校园借物项目 96 条为记录数；174 人报名与 121 人到场要区分。
- 周予安：突出需求、交互、可靠性边界、离线验证和跨职能协作。160 个问题中 116 到 138 为 72.5% 到 86.25%，增加 13.75 个百分点；8.2 秒到 6.4 秒是固定环境 P95 回放，不是线上平均响应。3 家商户、18 名客服是开放范围，460 次是生成次数。不得补增长、采纳、留存、付费、训练、多模态或自主规划经验；信息管理专业不能改成计算机专业。
- 何书宁：突出研究、交互、规则与模型边界、原型迭代。保留工业设计背景与课程团队性质，个人主持 6 场访谈不等于独立完成全部 12 场。24 人中的 14 与另一批 24 人中的 18 是不同参与者的体验观察，不是老年人结果、随机分组结论或商业转化。Coze 文本工作流不含 OCR、语音、RAG；不要创造实习。工作室 73 条借用记录不能挪到就医项目。技术与商业短板放正文外，以具体行动补强。

参考答案仅提供可行组织与事实边界；其他有证据、符合用户取舍的表达同样可以满分。
