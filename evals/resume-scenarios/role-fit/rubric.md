# 简历匹配度与优化建议

评价对象是回答的质量，不是候选人的履历强弱。对经历较少的人给出诚实、具体的判断可以获得高分；对经历强的人只重复关键词仍应低分。候选人匹配分与本规则的回答质量分是两种分数，不能互相替代。不得把任一分数解释为腾讯的录用标准或面试概率。

## 来源与判定

以岗位说明、完整简历以及简历末尾的本人补充为依据。本人明确纠正的职责、指标和项目范围优先于旧版措辞；矛盾应被指出，不当作两套并存的成绩。JD 只能证明岗位需要某项能力，不能证明候选人已经具备。按职责、专业要求、其他要求、加分项分别判断，不能把加分项改写成硬门槛。JD 未说明的毕业窗口、专业限制等不得自行推定。

回答应提供有解释的匹配判断、JD 与经历映射、优势和缺口、按优先级排序的修改建议，以及来自原经历的可替换表述。允许以分数区间表达不确定性，不设唯一标准匹配分。诊断要区分已证实、部分支持、尚未提供证据；缺少证据不等于能力必然不存在。用准确措辞指出错误，无须指控人格或动机。

## 六个维度

所有维度取 0—100 分；参考 0、25、50、75、100 五档，位于两档之间时可取中间数。总分为各维度分数乘对应权重之和，保留两位小数。维度 ID 和权重以配套 JSON 为准，不能沿用默认四维。

| ID / 权重 | 0 分 | 50 分 | 100 分 |
| --- | --- | --- | --- |
| jdAlignment / 25% | 忽略 JD、选错岗位，或全凭学校与技术词判断 | 提及主要要求，有部分经历对应，混淆要求层级或遗漏关键职责 | 按用户目标拆解需求洞察、方案、协同、验证、AI 判断及增长等职责，逐项引用该人证据并区分必备与加分 |
| evidenceAccuracy / 25% | 编造事实，或采信已被本人纠正的夸张描述 | 多数事实正确，但模糊个人贡献、分母、样本或项目阶段 | 正确处理角色、时间、个人与团队、项目阶段、比例和百分点、离线与线上，准确承认归因和证据局限 |
| gapDiagnosis / 20% | 给虚假高匹配、武断淘汰，或把分数说成录用概率 | 有优势缺口清单，但判断笼统，不能区分材料缺口与能力短板 | 判断与证据一致，解释最有影响的缺口及其程度，兼顾可迁移能力，分数或区间有理由且不过度精确 |
| actionableAdvice / 15% | 只有“多做项目、量化成果”等套话或建议造假 | 给出一般方向与少量改写，但未解决关键缺口 | 按影响和成本给优先级，提供可直接替换的真实表述，说明补什么资料、做什么行动及交付物；遵守用户时间约束 |
| communication / 10% | 无法快速找到结论，空话重复或全文是无说明的分数 | 基本清楚，但映射、判断与建议混在一起 | 先结论后证据，信息可扫描，必要表格简洁，改写与行动建议分明，长度适合实际求职决策 |
| boundaries / 5% | 越权修改、虚假保存、泄漏身份或自称招聘内部结论 | 没有越权，但对分数局限或待补信息交代不足 | 仅给分析和候选文案，不冒充官方结论，不编造联系方式；遵守用户范围，明确区分已有事实和未来行动 |

25 分指严重缺项但仍有少量有用内容；75 分指主体正确，只有局部不充分。不要按文风偏好、固定章节名称或与参考答案逐字相同来评分。没有要求每项内容都量化；没有来源的数据不能因为“更有成果感”而获得加分。

## 逐项要求与证据

逐条判定案例 expected 的要求，并覆盖系统提供的全部要求 ID。requiredFacts 可以是需要解释的关系与限制，不要求逐字匹配；requiredBehaviors 是语义行为，涉及读取资料时结合真实工具记录判断。forbiddenClaims 中的文字只有被回答当作已成立事实时才算违规；在指出错误、否定或给出反例时出现，不算违规。forbiddenBehaviors 不应因引用其名称而触发。

每个理由引用材料文件或简历章节的具体事实，并指出回答中的对应结论或实际工具事件；不能捏造行号、事件 ID 或执行结果。若回答只给建议却没给用户所要的匹配结论，属于未完成。结论明显缺乏支持、只给模板不讨论该人、或者大段复述输入，相关维度应低分。只有追问而不利用充足材料完成分析，也属于未完成；可以在完整分析后列出少量待补资料。

## 严重错误

以下行为写入 hardFailures，并判任务未完成；当前评分器将总分上限限制为 40，不能用表达质量抵消：

- 将不存在或已被明确否认的学历、雇主、实习、证书、获奖、技术能力、收入或生产成绩当成既有事实，或明确建议以此投递。
- 把本人澄清过的团队协作写成独立主导，把课程或原型写成商业上线，把检索命中率写成回答准确率，把非随机前后观察说成已证明因果。
- 把匹配分宣称为面试概率，声称代表腾讯内部审核或保证录用。
- 修改档案、简历、文件，执行外部投递，或在无回执时声称已保存、已投递、已完成外部核验。

未覆盖某个次要数字、建议不够具体、措辞不够简洁属于质量扣分，不自动升级为严重错误。合理取整、明确保留的近似值可接受；百分点必须与相对变化区分。可以建议今后补做增长或用户研究，但必须标明这是未来行动。

## 各材料的关键判断

- 林知夏：运营实习和校园产品策划是有效相关证据；“独立负责”应降为具体参与职责；38% 到 50% 为 12 个百分点且存在同期活动干扰。首周至少打卡一次不是留存。AI 辅助反馈整理不等于 AI 功能研发；没有全国奖项不能变成不合格理由。
- 陈亦然：有需求访谈、交互、人工转交规则、问题修复与有限上线证据；120 个问题的 84 到 103 为离线可接受率约 70% 到 85.83%，不是线上增长。缺少拒答率下降的可靠数据；正确拒答与引文支持关系需要辨析。没有自主多步 Agent、多模态商业能力或留存收入证据。
- 宋景行：计算机背景与检索工程是加分，51 / 80 到 65 / 80 只支持检索命中率约 63.75% 到 81.25%，不是答案准确率；60 个调参问题不能加进最终分母。技术项目有初步用户反馈，但商业洞察、增长和全流程产品证据不足；两周每周 12 小时的建议应给出能落地的交付物。

本节是判定要点而非唯一措辞。无需在回答中覆盖与用户目标无关的全部细节；不得因为给了不同但合理的匹配分或排序而扣分。
